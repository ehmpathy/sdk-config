# execution: schema-driven optional keys

design adopted (per vision + wisher's "schema is the final arbiter"): **safeParse-arbiter, no walk**.
- suppliers throw a typed tolerable-error taxonomy (`SupplyAbsentError` / `SupplyDeniedError`),
  raised only *after* retries (so a transient IAM denial is retried, never masked).
- `asFilledConfig` catches tolerable errors, substitutes `undefined` in place, and records the
  denied keyPaths with their reason. non-tolerable errors (throttle/network) rethrow at fill.
- `genGetConfig` hands the whole filled config to `safeParse` as the **sole arbiter** — no
  pre-walk, no prune, no `undefined`/`null` fabrication. a field that accepts `undefined`
  (`.optional()`/`.nullish()`/`.default()`) tolerates the miss; every other shape (required,
  nullable-only) rejects `undefined` and fails — which is correct, it was required-present.
- on a safeParse failure, `getAllBlockedSupplies` returns the denied supplies whose keyPath
  intersects a failure path (equal / ancestor-prefix / descendant-prefix). if any, hard-throw
  **always** (even prod/cloud) with the denied paths; a pure schema-drift failure (no denied
  intersection) keeps the extant env-gated warn-only behavior.
- no `z.toJSONSchema` walk, no schema-shape descent — retires the "most likely false" vision
  assumption and the whole class of data-loss bugs a hand-walk introduced.

## design notes

- **safeParse is the sole arbiter.** fill substitutes `undefined` on a tolerable supply error and
  records the keyPath + reason; the schema alone then decides pass-vs-fail. this makes "the schema
  is the final requirement" literally true — there is no second, hand-written optionality oracle to
  drift from zod.
- **no fabrication.** an unreadable value becomes `undefined` in place — never `null`. `undefined`
  is the honest fill: we could not even observe the value, so we do not substitute `null` (a value we
  never saw). a `.nullable()`-only field rejects `undefined`, so a denied nullable-only field fails —
  correct: `null` is a value, not an absence. a consumer who wants to tolerate marks the field
  `.nullish()`.
- **`getAllBlockedSupplies` is the one added transformer.** on a safeParse failure it intersects the
  recorded denied keyPaths with the error's issue paths (equal, or either a prefix of the other) and
  returns the supplies that intersect, tagged `verdict: 'block'` with their `reason`. an empty result
  means the failure is pure schema-drift (present-but-wrong), which keeps the extant env-gated
  behavior; a non-empty result is a denied-required hard failure.
- **two domain objects, orthogonal axes.** `SupplyOmission { key: { path }; reason }` is the
  fundamental, verdict-free fact fill records — a supply left `undefined` because it could not be
  read (`reason: 'absent' | 'denied'`, the supplier's error class). `SupplyTolerance<TVerdict>`
  extends it with the schema's `verdict: 'allow' | 'block'` (safeParse's call). the two axes are
  independent: an `absent` omission is `allow` under `.optional()` but `block` under a required
  field. fill emits `SupplyOmission[]`; `getAllBlockedSupplies` re-verdicts the schema-rejected ones
  to `SupplyTolerance<'block'>[]`. `genGetConfig`'s hard-throw carries `denials:
  SupplyTolerance<'block'>[]` plus a reason-aware hint so on-call can tell "fix the IAM grant"
  (denied) from "fix a typo'd path" (absent) with no re-run. all four types are exported from the
  public contract (`src/contract/sdk/index.ts` + `src/index.ts`). the generic is kept even though
  only `'block'` is constructed today — `verdict` is a timeless domain field (an allowed tolerance,
  e.g. an optional field that came back absent, is a real member of the type), not a YAGNI casualty.
  studied `ehmpathy/rhachet`'s keyrack `KeyrackGrantStatus`/`GrantAttempt` for prior art; kept our
  two-axis model because we have two arbiters (supplier + schema) where keyrack has one (the vault).
- **required-denied throws hard ALWAYS** (even prod/cloud), per wisher Q2; pure schema-drift keeps
  the extant env-gated warn-only behavior. the two are told apart by whether a failed safeParse path
  intersects a denied keyPath (`getAllBlockedSupplies` non-empty ⇒ denied-required).
- the tolerable-error taxonomy (`SupplyError`/`SupplyAbsentError`/`SupplyDeniedError`) is exported
  from the public contract so a third-party supplier (Vault/GCP/env-backed) can opt into tolerance
  without a deep import. an acceptance case proves a custom supplier's publicly-thrown
  `SupplyDeniedError` is tolerated through the public `getConfig`.
- the prod/cloud degrade path keeps the **honest documented `as z.infer<TSchema>` cast** (not a
  `z.any().parse` no-op): the value genuinely failed validation, so no runtime check could soundly
  produce that type — the cast names the deliberate assertion openly. `isAccessDeniedError` is a
  single shared transformer both aws suppliers import (no verbatim copy).
- **the walk was torn out.** an earlier iteration derived tolerance by a hand-walk of the schema
  (`getOneToleranceResolution` + `getOneConfigWithPathSet` + `getOnePrunedConfig`) so it could drop an
  optional ancestor or fill a nullable-only leaf with null. that walk was the source of every
  data-loss defect (a denied element wiped a whole optional array; a denied leaf dropped an optional
  ancestor's readable peers) and it re-implemented, by hand, optionality logic zod already owns. the
  decision-record test proves plain safeParse handles every genuinely-tolerable shape with no walk;
  the two shapes the walk uniquely "fixed" only passed by a discard of data we never observed, so
  they should fail loud instead. the teardown removes 3 transformers + ~14 tests and the bug class.

## contract narrowings vs the wisher-approved vision (need sign-off)

the vision result (`1.vision.yield.md`) was approved with two tolerance shapes that the final
no-walk design **no longer tolerates**. both are deliberate — they trade a fragile hand-walk for a
precise, loss-free contract — but they narrow the approved vision, so they need wisher sign-off.

- **nullable-only no longer fabricates `null`.** vision edgecase table said a `.nullable()`-only
  field denied ⇒ "substitute `null`". the final design does not fabricate a value we never observed;
  a denied nullable-only field fails loud. **consumer migration**: mark the field `.nullish()` (or
  `.optional()`) to tolerate a miss. rationale: `null` is a value, absence is `undefined`; the two
  are not the same and sdk-config must not invent the former for the latter.
- **ancestor-optional no longer tolerates a denied required leaf.** vision edgecase table said
  `a.b` optional + required leaf `a.b.password` denied ⇒ "omit the whole optional node `a.b`". the
  final design does not drop a present node to force a pass, because that also drops the node's
  readable peer fields (the array/peer data-loss bug). a present optional object must satisfy all its
  required children, so it fails loud. **consumer migration**: mark the specific **leaf** optional
  (`password: z.string().optional()`), not the ancestor object. this is strictly more precise — it
  tolerates exactly the field expected to be unreadable and never drops a readable peer. the
  cicd oidc-split example in both READMEs already uses this leaf-optional shape.

## known gaps (deliberately out of scope)

- **present-but-empty value is NOT tolerable**: "unreadable" means absent (not-found) or denied — a
  param/secret that exists but has an empty value is a real value problem, not an absence. the
  suppliers reject it with a plain `BadRequestError` (not a `SupplyError`), so fill does not tolerate
  it and `getConfig()` hard-throws regardless of field optionality. locked by `genGetConfig.test.ts`
  case22. if a consumer needs "empty ⇒ absent" for an optional field, that is a wisher decision (the
  suppliers would raise `SupplyAbsentError` on empty), not assumed here.
- **cicd oidc-split proof**: `genGetConfig.test.ts` case21 reproduces the wish's literal motivation
  scenario — one shared config, two jobs whose schemas are built from `process.env.GRANT` (active
  grant required, other grant's leaf `.optional()`), each denied on the other grant's param — and
  proves both the plan job and the apply job settle cleanly with the off-grant leaf tolerated. this
  is the "we need proof that we support this" the wish opened with, at the genGetConfig level
  (real-AWS denial proof still belongs to 5.3).
- **live-AWS proof of the denial path**: acceptance/integration exercise real AWS for the *absent*
  (not-found) branch; the AccessDenied (denial) branch is proven by unit tests. an end-to-end
  IAM-restricted-principal run belongs to the 5.3 verification stone (needs scoped creds / CI), not
  this execution stone.
- **retry backoff**: both suppliers retry a denial 3x with no delay (the retry loop pre-exists on
  main). so "persistent denial" ≈ "denied on every immediate attempt" — it satisfies the letter of
  vision Q6 ("tolerate only after retries") but a fixed 1-2s backoff would better honor the spirit
  (IAM propagation is seconds). deferred: a real sleep is a retry-mechanism change beyond this
  wish's scope and would slow the suite; flagged for a human/5.3 decision.
- **retry+classify loop duplicated across both aws suppliers**: the two suppliers carry a
  near-identical bounded-retry loop (attempt loop, not-found → `SupplyAbsentError`, empty-value
  rethrow, post-retry AccessDenied → `SupplyDeniedError`, else `MalfunctionError`); only the sdk
  client, not-found class, and empty shape differ. held at 2 copies per wet-over-dry (extract at the
  3rd). `isAccessDeniedError` is already the one shared piece. flagged so a 3rd supplier (Vault/GCP)
  extracts a `withSupplyRetryClassification` communicator-helper rather than a 3rd copy — which is
  also where a future retry-backoff fix should land (one place, not two).
