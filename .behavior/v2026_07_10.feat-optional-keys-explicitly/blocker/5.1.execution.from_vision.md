## the shipped design (the current, no-walk contract)

the design is **safeParse-arbiter, no walk** — a deliberate simplification from the vision's
original json-schema-walk proposal, reached with the human through this session:

- suppliers throw a typed tolerable-error taxonomy (`SupplyAbsentError` / `SupplyDeniedError`,
  base `SupplyError` now `abstract`), raised only *after* retries so a transient IAM denial is
  never masked.
- `asFilledConfig` catches tolerable errors, substitutes `undefined` **in place** (never
  `null`, never dropped), and records `{ keyPath, reason }`. non-tolerable errors rethrow.
- `genGetConfig` hands the whole filled config to `safeParse` as the **sole arbiter**. a field
  that accepts `undefined` (`.optional()`/`.nullish()`/`.default()`) tolerates the miss; a
  required or nullable-only field rejects `undefined` and fails.
- on a safeParse failure, `getAllBlockedSupplies` returns the denied supplies whose keyPath
  intersects a failure path; if any, hard-throw **always** (even prod/cloud) with the denied
  paths + a reason-aware hint; a pure schema-drift failure keeps the extant env-gated behavior.

this tears out the earlier hand-walk (3 transformers + ~14 tests) and, with it, the whole class
of data-loss bugs the walk introduced (a denied array element wiped a whole optional array; a
denied leaf dropped an optional ancestor's readable peers). the decision-record test
(`toleranceViaSafeParse.decision.test.ts`) proves plain safeParse handles every genuinely
tolerable shape with no walk.
