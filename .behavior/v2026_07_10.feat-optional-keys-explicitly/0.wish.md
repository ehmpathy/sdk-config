here's what a peer said

                                                                                                                              
  direct answers                                                                                                                                                                              
   
  "how do we supply which ones are optional?" — you don't supply a separate list. you mark the field .optional() (or .nullable()) in the zod schema. that is the signal. everything not marked
   stays required.                                                                                                                                                                          
                                                                                                                                                                                              
  "can we leverage the zod schema we already pass?" — yes, fully. sdk-config already receives the schema in genGetConfig. the change threads it into the fill step so fill can ask the schema 
  "is this keyPath optional?" and use that to decide tolerate-vs-throw. no new config surface, no keyPath list, no interpolation.
                                                                                                                                                                                              
  the resulting contract (exactly what you asked for)                                                                                                                                         
   
  - failfast by default: if a param can't be read (AccessDenied / not-found) and the schema marks it required, getConfig() throws — same strictness as today.                                 
  - tolerated only when explicitly optional: if the schema marks that keyPath .optional()/.nullable(), fill substitutes undefined and moves on; safeParse then accepts it.                  
  - transient errors always throw (throttle/network) regardless of optionality — never masked.                                                                                                
                                                                                                                                                                                            
  To make it env-conditional (plan vs apply), the only per-repo code is the schema reading process.env.GRANT:                                                                                 
                                                                                                                                                                                            
  // config.schema.ts — plan job marks apply-grant optional, and vice-versa                                                                                                                   
  const grant = process.env.GRANT ?? 'apply';                                                                                                                                                 
  const cicd = z.object({                                                                                                                                                                     
    username: z.string(),                                                                                                                                                                     
    plan:  grant === 'plan'  ? z.object({ password: z.string() }) : z.object({ password: z.string() }).optional(),                                                                            
    apply: grant === 'apply' ? z.object({ password: z.string() }) : z.object({ password: z.string() }).optional(),                                                                            
  });                                                                                                                                                                                         
                                                                                                                                                                                              
  plan job (GRANT=plan): apply optional → its denied param tolerated; plan required → present & read. apply job: mirror. exactly one grant required per job = true failfast.                  
                                                                                                                                                                                            
  the sdk-config handoff                                                                                                                                                                      
                                                                                                                                                                                            
  repo: ehmpathy/sdk-config
                                                                                                                                                                                              
  .what
    fill tolerates an UNREADABLE param (authz-denied or absent) ONLY when the                                                                                                                 
    schema marks that field optional/nullable. required fields still failfast.                                                                                                                
    optionality is read from the zod schema already passed to genGetConfig.                                                                                                                   
                                                                                                                                                                                              
  .why                                                                                                                                                                                        
    cicd oidc split: the plan job's reader role is IAM-denied on every ssm param                                                                                                            
    except .../cicd/grant=plan/*. today asFilledConfig eagerly fetches ALL $.at                                                                                                               
    refs before validation and hard-throws on the first denied one, so a                                                                                                                      
    restricted role can't resolve a config even when the denied fields are                                                                                                                    
    logically optional for that role. we want: failfast by default, tolerate                                                                                                                  
    only what the schema explicitly marks optional.                                                                                                                                           
                                                                                                                                                                                              
  .change                                                                                                                                                                                     
    1. genGetConfig.js: pass `schema` into asFilledConfig (it already has it).                                                                                                              
    2. asFilledConfig.js / fillRecursive: wrap `supplier.supply({ path })` in                                                                                                                 
       try/catch. on error:                                                                                                                                                                   
         a. classify tolerability of the ERROR: authz-denied                                                                                                                                  
            (AccessDeniedException) or absence (ParameterNotFound) => "tolerable                                                                                                              
            error"; anything else (throttle, network, unknown) => rethrow.                                                                                                                    
         b. classify optionality of the FIELD: is `keyPath` optional/nullable in                                                                                                              
            the schema? (see below)                                                                                                                                                           
         c. tolerable-error AND field-optional  => return undefined (omit key)                                                                                                                
            tolerable-error AND field-required  => rethrow (failfast, with the                                                                                                              
                                                   AccessDenied context intact)                                                                                                               
            non-tolerable-error                 => rethrow                                                                                                                                  
    3. optionality lookup (zod 4): derive once per getConfig via                                                                                                                              
       `z.toJSONSchema(schema)`, then for a dot-delimited keyPath walk the JSON                                                                                                               
       schema; a field is "optional" if, at any level along the path, it is not                                                                                                               
       in that level's `required[]` OR its type permits null. (json-schema route                                                                                                              
       avoids brittle zod-internal (`._zod.def`) coupling across zod minors.)                                                                                                                 
       cache the derived json-schema on the getConfig closure so it's computed                                                                                                                
       once, not per-ref.                                                                                                                                                                     
                                                                                                                                                                                              
  .acceptance                                                                                                                                                                                 
    - schema marks field OPTIONAL + supplier AccessDenied => getConfig resolves,                                                                                                            
      key omitted, safeParse passes                                                                                                                                                           
    - schema marks field REQUIRED + supplier AccessDenied => getConfig throws                                                                                                               
      fast (failfast env) with the denied path in context                                                                                                                                     
    - supplier THROTTLE/network error on any field (optional or not) => throws                                                                                                                
    - nothing denied => behavior byte-identical to today (no regression)                                                                                                                      
    - nested optional: `a.b` optional, `a.b.password` denied => tolerated                                                                                                                     
      (ancestor-optional implies subtree absence permitted)                                                                                                                                   
                                                                                                                                                                                              
  .consumer usage after release                                                                                                                                                               
    - config.schema.ts builds grant fields from process.env.GRANT (active =                                                                                                                   
      required, other = .optional()); default GRANT=apply                                                                                                                                     
    - config/prod.json: role.cicd.plan.password + role.cicd.apply.password, each
      a fixed $.at path (no interpolation)                                                                                                                                                    
    - .sql-schema-control.yml plan step: env GRANT=plan ; apply step: unset                                                                                                                   
                                                                                                                                                                                              
  The one design point I baked in for you: error-class tolerance is separate from field optionality. Both must hold to tolerate. That prevents an optional field from silently swallowing a   
  real throttle/outage — you keep failfast where it counts.
