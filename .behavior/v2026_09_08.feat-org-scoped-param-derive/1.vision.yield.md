# vision: org-scoped param derive

> a bare `$.at(aws::param)` derives `/{org}/{repo}/{choice}/{keyPath}` — **always, four segments**.
> the org is **declared, never passed**: the static config's `organization` field is the one source,
> and every ahbode sdk-config consumer already carries it (6 of 6).
>
> 🔴 **the field is REQUIRED. a config that omits it fails fast** (F8, ruled by the wisher). that
> strikes the wish's acceptance #2 — **the wish is amended on record** — and buys the guarantee it
> was after: the un-namespaced path two orgs could collide on is **unreachable**, over merely
> avoidable. it ships as a **minor**, since no external consumer exists to break (Q9).
>
> 🔴 **read F11 and F15 before the contract below.** `genGetConfig` has **no `org` key and no
> `repo` key**. both overrides this stone opened with are cut, and the sections that still name
> either are marked where they stand.

## the contract

```ts
// 🔴 the public boundary SHRANK. no key was added, and `repo?` was removed.
export const getConfig = genGetConfig({
  schema, statics, cache, suppliers, environment,
});  // ⛔ no `org` key (F11) and no `repo` key (F15). the config declares both.
```

```yaml
# config/prep.yml — the source of BOTH path segments
organization: ahbode        # required
repository: svc-notifications # optional — package.json `name` by default, npm scope stripped
```

🔴 **F15 struck the `repo` override, after this stone closed.** the vision opened with one
declared segment and one overridable one; the two are now supplied identically. every passage
below that contrasts them — the seam table's *"where `repo` threads today"*, the `repo`-hack
comparison, awkward #6 — describes the state **before** F15 and is left as written, since to
repoint it would report a survey that was never run. ⇒ `case=F15` carries what moved.

```
org source:   static config `organization`   >   ⛔ THROW
derive:       bare uri        →   /{org}/{repo}/{choice}/{keyPath}
              explicit uri    →   the explicit path, untouched   ← the derive never runs
              no org declared →   ⛔ BadRequestError, before any store read — whether or not
                                    a path needs the org (F8's `always` read)
```

⚠️ **a caller cannot force *no* org, only a *different* one**, and that choice is a config edit:
`"organization": "_"` derives `/_/{repo}/{choice}/{keyPath}` — its own namespace, never back in the
shared un-scoped pool, and still four segments (F5).

🔴 **and an `org` argument is not a smaller version of that.** a second source does not add one
degree of freedom, it multiplies the space: a precedence rule, then an absent-org state to make
illegal, then two error wordings per throw (`org` sits inside `organization`), then an optional
ARGUMENT for a REQUIRED VALUE, then a test case per source per throw. ⇒ **nobody asked for it**,
and the wish asked for a *declared* source. F11 carries the chain;
`ehmpathy/rhachet-roles-ehmpathy#674` carries the rule.

three internal seams move — one new op, one mechanical thread, one line of derive:

| op | change | width |
|---|---|---|
| `getOneOrg` (new, beside `getOneRepo.ts`) | `{ static } → OrgSlug`; **throws when the config declares none** (F8) and when the value is not a literal non-empty string. one source, so **one** remedy in the error text; trims a wrapper `/` so `"/ahbode/"` cannot yield `//ahbode/…` | a new file |
| `asFilledConfig` | threads `org: OrgSlug` through, exactly where `repo` threads today | **6 lines**, not one — `repo` sits at 6 sites: two signatures, then the entry call, the `asSdkConfigPath` call, and both recursive branches (array + object) |
| `asSdkConfigPath` | the derive template gains a segment; the explicit branch is untouched | **1 line** |

⚠️ **the middle seam is one *concept* and six *lines*.** `fillRecursive` is recursive, so a new
name must be re-passed at every descent. mechanical and low-risk — the compiler catches a missed
site, since the key is required (`rule.forbid.undefined-inputs`) — but "each one line wide" would
have been a false picture of the diff.

✅ **F8 made the derive seam *smaller*, not larger.** the org is non-nullable by the time it
reaches `asSdkConfigPath`, so there is **no branch at all**: the two-segment template is
**deleted** rather than kept behind a conditional. one template, one shape, zero code paths
(`rule.avoid.unnecessary-ifs`).

🟡 **there is no "base schema" mechanism today** — the consumer's schema is *"the SOLE arbiter"*
(`genGetConfig.ts`). so the requirement lands as a **check inside `getOneOrg`**, over a zod base
intersected into the consumer's schema. same behavior; the throw is ours to author, so it names the
field and the fix, over one zod issue among the consumer's own. F8 records the pick.

🔴 **the org is read where the config is parsed, and that is what makes the guarantee structural.**
`asStaticConfig` returns `{ config, org }` — there is exactly **one** route to a parsed config, so a
surface added later inherits the org requirement by construction, with no unvetted shape to reach.

⚠️ **the two names are derived at different moments, and that is forced, not chosen.** `repo` is
derived **once**, at factory time, from package.json. the org is read from the **static config**,
which is loaded **per fill**. two consequences a reader should not have to derive: the malformed-org
throw lands on the **first `getConfig()`**, never on import (the same moment every other config
error already lands); and the org is necessarily **per choice**, because there is no repo-wide read
to hoist it to.

## mental model

### how folks describe it to a friend

> "it's the github org above the repo. the param path already had the repo and the env in it —
> now it can have the org too, so two teams' `svc-notifications` don't fight over one path."

### analogies

- **a github org above a repo** — `ahbode/svc-notifications`, the same two words, in the same order
- **an npm scope above a package** — `@ahbode/svc-notifications`
- **a dns label** — you prepend a segment to disambiguate; you never rewrite the ones below it

### terms

| they say | we say |
|---|---|
| "the org prefix" | the `org` segment, first in the derived path |
| "our org field" | `organization` — the consumer's config key, our source |
| "the auto path" | the **derived** path (`explicitPath === null` ⇒ derive) |
| "the hardcoded path" | the **explicit** path — passthrough, never touched |
| "it can't find the param" | `SupplyAbsentError` → a blocker with `reason: 'absent'` |

`organization` (the declared field) and `org` (the derived segment) are two distinct terms,
as `name` → `repoName` already are in this repo. see fulcrum F4.

## evaluation

### against the wish's acceptance

| # | acceptance | how it is met |
|---|---|---|
| 1 | org available ⇒ `/{org}/{repo}/{choice}/{keyPath}` | ✅ `case=1` |
| 2 | ~~no org ⇒ byte-identical to today~~ | 🔴 **STRUCK by the wisher** — see below |
| 3 | explicit path untouched | ✅ `case=3` — an explicit path still passes through verbatim. ⚠️ narrowed: it holds under a **valid** org; an absent or malformed one throws before the path is reached (F8) |
| 4 | a declared **source**, not an override alone | ✅ the config `organization` field — required, and the **only** source. 🔴 F11 goes past what the wish asked: it asked for a declared source *beside* an override, and there is no override at all |
| 5 | every one clamped, red-before / green-after | ✅ each case names its clamp. ⚠️ #2's clamp was **replaced**, not dropped — see below |

#### 🔴 acceptance #2 is struck, and #5's clamp is replaced

the wish demanded a byte-identical two-segment derive when no org is available, and named it
*"the half most likely to regress unnoticed"*. the wisher's F8 verdict removes that derive:

> **"and if omitted, failfast; we can just enforce this as a required base schema"**

⇒ **there is no absent-org derive left to be backcompatible with.** on record here rather than
glossed, because a struck acceptance criterion is a scope fact the criteria stone must inherit.

**it is coherent with the wish's *spirit*, and not with its letter.** #5's warn names the real
hazard — *"the derive grew an org segment unconditionally"* — and its danger was that the growth
would be **silent**. F8 grows it **loudly**, so the hazard is answered by the failfast rather than
by a fallback.

⇒ and the clamp #5 asked for is replaced by one that guards the failure the **requirement**
introduces: a build that forgets the throw does not fall back to two segments — it splices a blank
and derives `//svc-x/…` or `/undefined/svc-x/…`. `case=2` `[t1]` seeds the store at the old
two-segment path and asserts `supplied.paths` is **empty**, which is the one assertion that goes
red on a fallback that quietly works.

### why this, over the `repo` hack that already works

the target path shape is reachable **today**, with no change to sdk-config at all:

```ts
genGetConfig({ …, repo: 'ahbode/svc-notifications' })
// derives /ahbode/svc-notifications/prep/database.password — the exact target
```

`asSdkConfigPath` splices `repo` verbatim, so a slash inside it yields the org segment for free.
any repo could do this tomorrow. so the wish does **not** buy a new capability — it buys three
things the hack cannot:

| the hack | this wish |
|---|---|
| every consumer hand-passes a doctored value at its `genGetConfig` call | the org is **declared once, in config** — acceptance #4, and the only shape a shared template can ship |
| `repo` silently means "org/repo" — one term, two concepts | `org` and `repo` stay one term, one concept (`rule.require.ubiqlang`) |
| the package.json fallback cannot produce it, so a hand-passed value becomes mandatory at every call site | the fallback still works, and the org needs no argument at all |

⇒ **the value is ergonomics and vocabulary, not capability.** stated plainly here, because a
reviewer who spots the hack will ask — and because it caps how much machinery this deserves.

### pros

- **zero call-site changes for the repos that matter** — all 6 ahbode sdk-config consumers
  already declare the field (16 ahbode repos declare it in total), so F8's requirement costs them
  not one edit
- **the smallest possible seam, and F8 made it smaller** — one template, no branch. the org is
  non-nullable by the time it reaches `asSdkConfigPath`, so the two-segment template is **deleted**
  rather than kept behind a conditional (`rule.avoid.unnecessary-ifs`)
- 🔴 **the api surface does not move at all.** the public surface is `src/contract/sdk.ts` (F10),
  and it exports `genGetConfig` plus the two supplier factories — **`asFilledConfig`,
  `asSdkConfigPath`, `getOneRepo`, and `getOneOrg` are not exported**, so every seam is internal.
  under F11 **no key is added** to `genGetConfig`, so the outward *type* is byte-identical.
  suppliers need no change either: `asFilledConfig` computes the path and hands the supplier a
  finished string
- 🔴 **the api surface is not the whole story, and this pro is bounded by F8.** a newly required
  **config field** is a runtime break even where the type signature stays compatible. see the
  first con
- **the ambiguous state is unreachable, over merely discouraged** — no config can boot into the
  un-namespaced path two orgs could share (F8). that is a stronger guarantee than the wish asked for
- **it reuses the domain's own word** rather than a new key to migrate every consumer onto

### cons

- ✅ **a breaking change with an empty blast radius — and it ships as a MINOR.** F8 makes a config
  field newly required, so any consumer that lacks `organization` throws on upgrade. measured:
  **6 of 6** ahbode consumers already declare it. the wisher closed the external half — *"no one
  uses this repo yet"* (Q9) — so the break is real and nobody can experience it. 🟡 **that is a
  fact about today**: once an external consumer adopts, a change of this shape owes a major.
- 🔴 **and it fires even where the org is never used.** an all-explicit repo, which consumes no
  derive at all, is still held to the requirement (F8's `always` read, demoed at `case=4` `[t2]`).
  that is the one place the verdict charges a repo for a value it will not read. LAZY is the clean
  rework, and it is one guard.
- **presence was a weak opt-in; F8 dissolves that, and narrows the opt-out.** a repo that carried
  `organization` for its own reasons could once get an org-scoped path it never asked for. under a
  requirement no one declares the field without the error that teaches what it feeds, so presence
  is never accidental. its way out is `"organization": "_"`, which derives `/_/{repo}/{choice}/…`
  — a different namespace, over the old path. **raised and ruled irrelevant by the wisher** (F5).
- 🔴 **the opt-out is a config edit, and there is no call-site lever at all** (F11). a consumer who
  wants a different org for one deployment edits that deployment's config file. ⇒ the cost is real
  — a value that varies per call site has nowhere to live — and it is what buys the guarantee that
  the org has exactly one source.
- **sdk-config starts to read a key it does not own — and now to *demand* it.** `organization` is
  the consumer's field; we impose a shape on it (a literal string, F2) and, since F8, its
  presence. that is a real widening of the dependence, and it is what buys the guarantee.
- **it widens the wish's literal scope to `aws::secret`**, since the derive is scheme-agnostic (F3).
- **it is necessary and deliberately not sufficient.** the bare form still misses until each param
  is moved to the derived path. ✅ **ruled**: that is intended — this ships the **target
  convention**, and the wisher drives the migration to it (F6, Q3). so it is a cost in *sequence*,
  never in correctness: the adoption of any one repo is two steps, and this is the first.

## open questions & assumptions

### assumptions

1. ✅ **`organization` is the right source** — no longer an assumption. **ruled by the wisher**
   (F1, 2026-09-08). grounded: all 6 ahbode repos that depend on sdk-config declare it (16 ahbode

2. **an ssm parameter name tolerates a fourth hierarchy level.** aws documents a limit on
   hierarchy depth and total name length; a 4-segment path is far inside both. **not verified
   against the docs in this stone** — flagged for execution research (external research below).
3. **no repo in the wild relies on the bare derive today.** verified across `ahbode/*` and
   `ehmpathy/*` — 30 `aws::param` usages, all explicit, zero bare. repos outside those two orgs
   are unverified.
5. ✅ **NEW, and it is what F8 rests on: every sdk-config consumer either declares `organization`
   or can be made to.** verified for the population we can see — **6 of 6** ahbode consumers
   declare it — and the wisher closed the half i could not measure: *"no one uses this repo yet"*

4. **the static config is available before the fill.** verified: `genGetConfig.ts:44` loads the
   static config, then calls `asFilledConfig` at `:50`. the org is readable with no new i/o.

**Q3 ✅ [ruled by the wisher, 2026-09-08] — the shape stands, and the params migrate to it.**

the question was: the org segment alone does **not** make a bare placeholder point at the params
that exist today. every org-scoped param in the wild reads
`/ahbode/svc-notifications/database/role/cicd/for-plan/password` — **no `{choice}` segment, a
slash-joined keyPath** — while this wish derives
`/ahbode/svc-notifications/prep/database.role.cicd.for-plan.password`.

> *"we want this shape basically — `/ahbode/svc-notifications/prep/database.role.cicd.for-plan.password`
> … and we'll get everyone else to adhere."*

⇒ **the mismatch is the point, not a defect.** the derived shape is the **target convention**; the
params in the wild are what migrates to it. `{choice}` stays, the dot-joined keyPath stays, the
slash-joined `org/repo/choice` prefix is wanted. the move is the wisher's downstream work, and this
behavior is what gives it a target to aim at. F6 ruled; see its entry.

**Q4 ✅ [ruled by the wisher, 2026-09-08] — no force-off. drop it.**

i carried this at 70%, the lowest of the seven, with the doubt stated in the open: nobody asked
for `org: null`, and `rule.prefer.wet-over-dry` says wait for the need.

> *"no force off. if they want a bare placeholder, they can set `org: '_'` or some other
> placeholder"*

⇒ **the doubt was right and the substitute is better than the plain drop i offered.** `'_'` does
not reproduce `null` — it derives `/_/{repo}/{choice}/…`, a **third namespace**, over a fall back
to the shared one. three consequences follow:

- **the derived shape stays uniform** — every org-aware repo derives four segments, always. a
  `null` would have let a declared repo drop to three, which re-opens the very ambiguity the org
  segment exists to close
- **the opt-out is visible** — `_` shows up in the path, the console, and the error text
- **an opt-out lands somewhere, over nowhere** — it cannot collide with the shared no-org
  namespace it was fleeing

🔴 **when i wrote this i added "acceptance #2 is untouched — a repo with no `organization` still
derives two segments."** F8, ruled minutes later, struck exactly that. so F5 and F8 together leave
**no** route to a three-segment path: a caller cannot ask for one, and a config cannot fall into
one. the internal `getOneOrg` never returns `null` — it throws.

🔴 **and F11 moved where the opt-out is written.** the wisher's words name `org: '_'` because an
`org` argument existed at the time; there is no such key now, so the same opt-out is
`"organization": "_"`, in the config. ⇒ the **verdict** is unchanged — a different literal, never a
force-off — and only its surface moved.

**Q5 [research]** — the one item here that neither logic nor this repo can settle: aws's documented

**Q6 [research] — put to the wisher 2026-09-08, and left unanswered. it stays a research item, and

⇒ it changes the **urgency**, never the design. a second org already in that account means

**Q7 [answered] — no gate, for symmetry.** `"Acme Inc"` is a legal literal and derives a param name

**Q8 ✅ [ruled by the wisher, 2026-09-08] — ALWAYS, never lazy.**

F8's verdict said *"a required base schema"* — clear on **what**, silent on **when**. i took

> **"always, exactly cause lazy is a landmine"**

⇒ **the word is exact.** LAZY does not merely relax the rule — it **arms a trap and hides the

⇒ **the explosion is separated from its cause by both time and author.** and the all-explicit repo
is exactly the population F8 exists to protect (F1's weak opt-in), so LAZY leaves the defect alive
in the one place the verdict aimed at.

the cost ALWAYS pays is on record: an all-explicit repo throws for a value it will never read
(`case=4` `[t2]`, edgecase row 2). ⇒ **real, immediate, and visible** — which is what parts it
from LAZY's cost: deferred, invisible, and paid by someone else.

## what is awkward?

1. ~~**the wish's "why it matters now" overstates what this alone buys.**~~ ✅ **resolved by the
   wisher (2026-09-08)** — it does not overstate; i had the direction backwards. the params in the
   wild carry no `{choice}` segment and a slash-joined keyPath, and **they are what changes**: the
   derived shape is the target convention, and *"we'll get everyone else to adhere"*. so the org
   segment is required, this change is deliberately not sufficient on its own, and the adoption of
   any one repo is two steps — this one, then the move. no awkwardness remains; the sequence is by
   design (Q3, F6).

2. 🔴 **sdk-config reads a key it does not own — and now DEMANDS it.** `organization` belongs to
   the consumer's schema. we read it, we impose a shape on it (F2), and since F8 we refuse to boot
   without it. the alternatives are each worse (a universal source flips every repo; a key we own
   means a migration for every consumer) — ⚠️ **but F8 closed the gap between A and D**: a required
   field *is* a migration for every consumer that lacks it, which was D's whole disqualifier. A
   still wins on ubiqlang and on the measured 6-of-6, and the argument is now narrower than it was.
   this is the awkwardness a future reader will squint at hardest.

3. ✅ ~~**presence is a weak signal for intent.**~~ **dissolved by F8.** the repos that declared
   `organization` did not thereby declare *"scope my params by org"* — but under a requirement no
   one declares the field without first reading an error that says what it feeds. so presence is
   never accidental, and the design no longer leans on a fact of the current world. ⇒ this was
   F1's 15% doubt, and the wisher's second clause removed it rather than accepted it.
   (a related raise — that F5 makes the opt-out a **one-way door** — was **ruled irrelevant**.)

4. **`repoName` already has a related wart, and this makes it visible.** a scoped package name
   (`@ehmpathy/foo`) would derive `/@ehmpathy/foo/{choice}/…` — a slash inside the "repo" segment,
   an accidental org-scope by another route. neither cited repo is scoped, so this stays untouched
   here, and it hints that `org` should not try to parse itself out of the package name (F1-C).

5. ✅ ~~**two words in the same neighborhood, and now one contains the other**, so an error that
   names its source cannot do it with the bare word~~ — 🔴 **gone with F11.** `org` sits inside
   `organization` still, and it no longer costs a thing: one source means the error has one field
   to name, so no form is owed that tells two apart. ⇒ the cost was **a property of the second
   source**, never of the term (F4 stands; its one recorded cost does not).

6. ✅ ~~**the two names are derived at different moments, and one of them cannot be moved.**~~
   ~~🔴 **F11 widened the asymmetry**: `repo` takes an override and the org does not.~~
   **BOTH halves are resolved by F15.** the placement half: `repo` is no longer read at factory
   time — it is read per fill, inside `asStaticConfig`, beside the org, so the two now sit at the
   same point in the call graph. the override half: there is no `repo` override, so the pair is
   supplied identically. ⇒ nothing is left for a reader to trace.

   🟡 and the paragraph F11 wrote to defend the asymmetry — *"an override picks between two
   sources that both exist; an org override would mint a second"* — was the argument F15 struck.
   an override that picks is still a third source. see `case=F15`.

7. ✅ ~~**the `repo` hack and this feature stack silently.**~~ **narrowed by F15.** the argument
   that carried the hack is gone, so `repo: 'ahbode/svc-x'` is unreachable. what survives is a
   config that hand-declares `repository: 'ahbode/svc-x'` — the author's own value, in their own
   file, over a value an argument could smuggle in. and the scoped-name twin (`@ehmpathy/svc-x`)
   is **fixed**, not documented: `asRepoSegment` strips the scope, because a scope names an org
   and the org is already its own segment.

8. ✅ ~~**the public key and the internal key have different types.**~~ **resolved by F8, and then
   moot under F11.** F8 collapsed the two types — `getOneOrg` throws rather than returns `null`, so
   the nullable state left the codebase. F11 removed the public key altogether, so there are no
   longer two keys to disagree.

9. ✅ ~~**an optional ARGUMENT for a required VALUE reads as a contradiction.**~~ 🔴 **cut, over
   documented.** the contradiction was real — a type that says *"you may omit this"* beside a
   runtime that says *"one of you must supply it"* — and a `.why` line would only have explained it.
   ⇒ **the repair was to delete the argument** (F11). the disjunction the signature could not
   express is gone, because there is no disjunction.

10. 🔴 **the requirement fires where the value is never read, and no signature says so.** an
    all-explicit repo consumes no derive and is still refused (F8's `always`). that is deliberate —
    LAZY would leave the weak opt-in alive (Q8) — but from inside such a repo it reads as a demand
    with no purpose, and the error text is the only place the reason can live. ⇒ it must say
    *why* the field is required, not merely *that* it is.

11. 🔴 **the test diff is larger than the source diff, and that inversion is the honest signal.**
    the source change is one template plus one new op; the test change touches every case in
    `asSdkConfigPath.test.ts`, the integration fixture, every `asFilledConfig` call site, and
    **real aws params** in the acceptance suite, which must be re-created at four-segment paths.
    a reviewer who sizes this change by its source diff will underestimate it.

12. 🔴 **an ABSENCE needs a clamp, and only the type system can hold one.** F11 deleted the `org`
    key, and no runtime test can go red when someone adds it back — the code would simply work. so
    the clamp is a `@ts-expect-error` on a `genGetConfig({ …, org: 'acme' })` call
    (`genGetConfig.integration.test.ts`, `case=6` `[t2]`), which fails to compile the moment the key
    returns. ⚠️ it reads as a strange test, and it is the only shape that guards a freedom that was
    cut (`ehmpathy/rhachet-roles-ehmpathy#675`).
