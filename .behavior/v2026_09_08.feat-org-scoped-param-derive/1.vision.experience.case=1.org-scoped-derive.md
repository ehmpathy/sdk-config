# case=1 — the bare placeholder derives an org-scoped path

> cells: `r5` (runtime · config-field · bare · present) · `a3` (author)
> feel = **happy** · care = **critipath**

## narrative — the author, then the runtime

maya ships `svc-notifications` for **ahbode**. her config already opens with
`"organization": "ahbode"` — it has since long before this change, as it does in all 16 of
ahbode's services.

today she adds the rds cicd password. the extant move is to hand-author the full param path into
the placeholder, and get it subtly wrong the first two times. instead she writes the bare form
the `persist-with-rds` template ships:

```json
{ "organization": "ahbode",
  "database": { "role": { "crud": { "password": "$.at(aws::param)" } } } }
```

she writes no path. she passes no new argument to `genGetConfig`.

at boot, the cicd job calls `getConfig()`. sdk-config reads `organization` from the static
config it already loaded, and derives:

```
/ahbode/svc-notifications/prep/database.role.crud.password
```

the param is there. the password resolves. maya never typed a path.

the "aha": **the org she already declared for her own reasons became the namespace that keeps
her repo apart from another org's `svc-notifications` in the same aws account.**

## `[tn]` sketch

```ts
given('[case1] a config that declares organization + a bare aws::param placeholder', () => {
  // config/prep.json:
  //   { "organization": "ahbode",
  //     "database": { "role": { "crud": { "password": "$.at(aws::param)" } } } }

  when('[t0] getConfig() is called with no org argument', () => {
    then('the supplier is asked for the org-scoped path', async () => {
      await getConfig();
      expect(supplied.paths).toContain(
        '/ahbode/svc-notifications/prep/database.role.crud.password',
      );
    });

    then('the value resolves onto the typed config', async () => {
      const config = await getConfig();
      expect(config.database.role.crud.password).toEqual(PARAM_VALUE);
    });
  });

  when('[t1] the same config is loaded for choice=prod', () => {
    // config/prod.json carries the same two lines; a second factory is built on
    // the prod environment, so the derive runs again with only `choice` changed
    const getProdConfig = genGetConfig({ ...input, environment: PROD_ENVIRONMENT });

    then('only the choice segment moves — org and repo hold', async () => {
      await getProdConfig();
      expect(supplied.paths).toContain(
        '/ahbode/svc-notifications/prod/database.role.crud.password',
      );
    });
  });
});
```

## what this case pins

- the org segment lands **first**: `/{org}/{repo}/{choice}/{keyPath}`
- the source is **declared, not passed** — zero call-site changes (wish acceptance #4)
- the `{choice}` and `{keyPath}` halves are byte-identical to today's derive
- 🔴 **this is now the ONLY shape the derive produces.** under F8 the org is required, so there is
  no second template to fall to and no branch to pick between them. ⇒ *"the org segment lands
  first"* is a fact about every derived path, over a fact about the org-declared ones
