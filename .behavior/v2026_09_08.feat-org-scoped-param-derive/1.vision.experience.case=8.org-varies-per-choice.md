# case=8 — two choice files declare different orgs, and each derives with its own

> 🔴 **added downstream, by the `r5` peer review of the verification stone.** the behavior was
> already implemented and already green; the **catalog never named it**, which is the drift
> `rule.require.experience-catalog-evolution` calls a blocker. the contract grows here to hold it.

> cell: `f2` (axis F = `divergent`) · exercised by `genGetConfig.integration.test.ts [case29]`
> feel = **happy** · care = **critipath** — a core usecase depends on it, and the hazard is a
> plausible refactor rather than a user mistake

## narrative — the sandbox org, and the refactor that would silently delete it

dara runs `svc-jobs` in `ahbode`. she wants her **test** deployment to read params from a throwaway
org, so a broken test run cannot touch a real param. she edits two files:

```yaml
# config/test.yml
organization: org-of-test     # the sandbox
database:
  password: $.at(aws::param)
```

```yaml
# config/prep.yml
organization: org-of-prep     # the real one
database:
  password: $.at(aws::param)
```

one repo, one `genGetConfig` call site, two orgs:

```
CONFIG=test  →  /org-of-test/svc-jobs/test/database.password
CONFIG=prep  →  /org-of-prep/svc-jobs/prep/database.password
```

⚠️ **the org tracks the CHOICE, and that is structural rather than chosen.** the org's source is the
**static config**, which is loaded **per fill** (`genGetConfig.ts` loads the statics, then calls
`asFilledConfig`). there is no repo-wide read to hoist it to, so per-choice is not a feature someone
designed — it is what the load order already is.

### the hazard, and it will arrive dressed as a cleanup

`repo` is derived **once**, at factory time, from `package.json`. the org is read **per fill**. a
later author meets that asymmetry, reads it as an inconsistency, and hoists the org to factory time
so the two names match.

⇒ **that refactor silently re-points every derived path in every repo whose choice files disagree.**
no error, no type failure, no test — dara's `prep` deployment quietly reads from `org-of-test`, or
the reverse, and the first symptom is a param miss in an environment nobody changed.

🔴 **until this case was written, not one test could catch it.** all three `config/*` fixtures in
this repo declare the same `test-org` — so a build that read one file, cached across choices, or
hoisted to a module singleton derived the **right path anyway**, and every suite stayed green.

## `[tn]` sketch

```ts
given('[case8] two choices in one repo declare DIFFERENT orgs', () => {
  // ONE repo, ONE statics glob, ONE schema — the only variable is `environment`.
  // that is what makes the claim exact: were the org keyed to any other input,
  // both `when`s would derive the same path.
  const base = {
    schema: testSchema,
    statics: `${TEST_CONFIG_MULTIORG_DIR}/*.yml`,
    suppliers: [genNotedParamSupplier({ paths, verdict: 'supply' }), fakeSecretSupplier],
    repo: 'test-svc',
  };

  when('[t0] the `test` choice is filled', () => {
    const paths: string[] = [];
    const getConfig = genGetConfig({ ...base, cache: createCache(), environment: testEnv });

    then('it derives with test.yml own org', async () => {
      await getConfig();
      expect(paths).toEqual(['/org-of-test/test-svc/test/database.password']);
    });
  });

  when('[t1] the `prep` choice is filled, same repo, same statics', () => {
    const paths: string[] = [];
    const getConfig = genGetConfig({ ...base, cache: createCache(), environment: prepEnv });

    then('it derives with prep.yml OWN org, never test.yml', async () => {
      // the two assertions are ONE claim: the org tracks the CHOICE, and a
      // build that resolved it once would leak `org-of-test` into this path.
      await getConfig();
      expect(paths).toEqual(['/org-of-prep/test-svc/prep/database.password']);
      expect(paths[0]).not.toContain('org-of-test');
    });
  });
});
```

## what this case pins

- **the org is a property of the PARSED FILE, never of the repo.** it varies per choice because the
  static config varies per choice, and there is no earlier moment at which it could be read
- ⚠️ **`[t1]`'s second assertion is the clamp, and it is a NEGATIVE one.** `not.toContain('org-of-test')`
  goes red the instant a build resolves the org once and reuses it — which is the exact shape the
  hoist refactor takes, and the one failure a positive assertion alone would miss if the two orgs
  ever shared a prefix
- 🔴 **a dedicated fixture dir is required, and its absence is why this went unclamped.**
  `TEST_CONFIG_MULTIORG_DIR` exists solely so the two choice files **disagree**. every other fixture
  in the repo agrees, and agreement is precisely what makes the defect invisible
- 🟡 **the drift is bounded, and the bound is what makes `divergent` a feature over a hazard.**
  `environment` is fixed per `genGetConfig` instance, so one process sees **one** choice and
  therefore **one** org. two orgs never coexist in a run — they differ across **deployments**, which
  is what makes the test-org sandbox expressible at all
- ⇒ **it is a critipath because the hazard is a REFACTOR, not a mistake.** a user cannot stumble into
  it; a maintainer can, while they believe they tidy an inconsistency. there is no workable fallback
  once the hoist lands, since every derived path moves at once and none of them announces it
