## the defect found AND fixed at this gate

> **jest globbed the rmsafe recycle bin, so deleted tests still ran.**

```
FAIL .agent/.cache/repo=ehmpathy/role=mechanic/skill=rmsafe/trash/src/index.integration.test.ts
  ● Test suite failed to run
    ENOENT: no such file or directory, open '…/trash/src/index.ts'
```

⇒ F10 deleted `src/index.integration.test.ts`; `rmsafe` moved it to its trash **inside the repo**;
`testMatch: ['**/*.integration.test.ts']` globs the whole repo, so the deleted suite still ran — and
failed, since the source it imports is gone.

### the root cause, over the symptom

🟡 **an ignore file cannot bound jest at all** — it globs, and **jest does not read `.gitignore`.**
so the first read, *"a gitignore was deleted"*, named a fact that could not have been the cause.

⚠️ **and the fact itself has since changed, which moves the diagnosis not at all.** this section
once read *"the trash dir's `.gitignore` is present and correct"*; it is **gone from disk as of
2026-09-20**, and the deletion is staged. it is inert — `.agent/.cache/.gitignore:6` is `*`, so
every path under that dir is ignored whether or not the nested marker exists. ⇒ the one cost is an
unrelated deletion in this behavior's diff; a restore was attempted and the `git checkout` is
denied to this role, so it stands for the human to accept or drop at commit time.

⇒ so the symptom fix (delete the stale file) would recur on the **next** `rmsafe` of any test file.
the cause is the glob (`rule.require.solve-at-cause`).

### the repair — three configs, one line each

```ts
// .note = `.agent/` holds the rmsafe RECYCLE BIN, so a deleted test file
//         lives on there. jest globs the whole repo and does not read
//         `.gitignore`, so without this a deleted suite is still collected —
//         and it fails, since the source it imports is gone.
testMatch: ['**/*.integration.test.ts', '!**/.yalc/**', '!**/.agent/**'],
```

✅ **it follows the file's own precedent** — `'!**/.yalc/**'` was already there for the identical
reason, so this is the established shape rather than a new one.

| proof | before | after |
|---|---|---|
| integration suites collected | **7** | **5** |
| trash suites that ran | 2 | **0** |

⇒ two stale suites left the run: `trash/src/index.integration.test.ts` (failed) and
`trash/src/domain.operations/zzprobe.integration.test.ts` (green, and equally should never run).
**the green one is why this mattered**: a green from a deleted file is a green nobody can trace.

### what was actually wrong

role:

| | account | role |
|---|---|---|
| the keyrack profile `ehmpathy.test.ehmpath` | **805192865516** | `ehmpathy-demo-for-grove` |
| what every failed test used | **261599400667** | `ahbode-camp-grove-role` |

`ambient` — the tell that keyrack was never sourced — and the row took it as evidence that the rack

### the repair

```ts

useKeyrack({ env: 'test', owner: 'ehmpath', mode: 'strict' });
```

| gate | before | after |
|---|---|---|

role, so `mode: 'strict'` alone is necessary and **not** sufficient. dispatched upstream to
