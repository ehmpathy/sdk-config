# vision.experience.dimensions — org-scoped param derive

## .what

the orthogonal axes this behavior varies over, and the product walked. the inventory
(`1.vision.experience.case=_.md`) verdicts every cell; this file declares the space.

## the axes

### A. actor — who encounters it (3)

| value | who | when |
|---|---|---|
| `author` | a human who writes `config/*.json` + wires `genGetConfig` | authoring time |
| `runtime` | the system — a lambda / cicd job that calls `getConfig()` | boot time |
| `oncall` | a human who reads the thrown error | failure time |

`system` is a legitimate actor value — the derive runs unattended in cicd, with no human to prompt.

### B. org supply — where the org segment comes from (~~4~~ → **3**, F11)

| value | shape | outcome |
|---|---|---|
| `absent` | no `organization` key in the static config | ⛔ **refused** (F8) |
| `config-field` | static config carries a top-level `organization: "ahbode"` | ✅ derives |
| ~~`override`~~ | ~~caller passes `genGetConfig({ org: 'ahbode' })`~~ | 🔴 **DELETED (F11)** — there is no `org` key |
| `malformed` | a declared org that is not a literal non-empty string — an object, a number, a `$.at(...)` placeholder, or a blank | ⛔ refused |

🔴 **`absent` moved from *live* to *refused* on the wisher's F8 verdict** (*"if omitted, failfast"*).
it was the wish's acceptance #2 — the byte-identical two-segment derive. that derive no longer
exists, so the value survives as a **shape an author can express** and no longer as an experience
that produces a path.

🔴 **`override` was DELETED outright on F11.** it is not a value an actor can express by any means,
so it is not an experience — it is a region of the space that ceased to exist. ⇒ **that is the whole
claim F11 rests on**: one degree of freedom cut, and a *quarter of axis B* went with it, plus every
cell that quarter paired with on `A`, `C`, `D`, and `E`.

⇒ **B now splits cleanly into a valid half and an invalid half**, and the split governs three of
the five inert regions below:

| half | values | what varies |
|---|---|---|
| **valid** | `config-field` | `C` decides derive-vs-passthrough; `D` decides fill-vs-miss |
| **invalid** | `absent` · `malformed` | ⛔ naught — the refusal precedes both `C` and `D` |

✅ **B no longer fuses two concepts, and that resolution is F11's.** it once collapsed *source*
`{absent, config-field, override}` × *validity* `{literal, malformed}` into four values, and that
collapse owed a pin: the `override × malformed` cell had to demo what the config cell could not —
that the error names **which source** supplied the bad value.

⇒ **one source dissolves the product.** `B` is now source-free: `{absent, config-field, malformed}`
reads as validity alone. the collapse is gone, the pin it owed is gone, and `case=4` `[t3]` is
re-subjected from *a malformed override* to *a blank declared org* — the same refusal, one source.

| cell | pinned at |
|---|---|
| `config-field × malformed` | `case=4` `[t0]`/`[t1]`/`[t3]`, plus the yield's edgecase rows |
| ~~`override × malformed`~~ | 🔴 **gone** — no override exists to malform |

### C. uri form — how the placeholder is written (2)

| value | shape |
|---|---|
| `bare` | `$.at(aws::param)` — path is derived |
| `explicit` | `$.at(aws::param/ahbode/svc-x/db/pass)` — path is given |

### D. param state at the derived path — what the store holds (2)

| value | meaning |
|---|---|
| `present` | a value sits at the path the derive produced |
| `absent` | no value sits there (`SupplyAbsentError` → schema decides) |

### E. account tenancy — how many orgs share the parameter store (2)

| value | the account holds |
|---|---|
| `solo` | one org's repos |
| `shared` | two orgs, each with a repo of the same name |

🔴 **this axis was missed on the first walk, and the self-review caught it.** it is the wish's
whole motive — the collision only *exists* under `shared` — yet the first four axes could not
express it, so no cell held it and no case demoed it. added, and demoed by `case=7`.

### F. org agreement across choice files — does every config file declare the same org? (2)

| value | shape | outcome |
|---|---|---|
| `uniform` | `test.yml` and `prep.yml` both declare `organization: ahbode` | one org for every choice |
| `divergent` | `test.yml` declares `org-of-test`, `prep.yml` declares `org-of-prep` | 🔴 **each choice derives with its OWN file's org** |

🔴 **this axis was missed on the first walk, and the r5 peer review caught it downstream** — a real
test (`genGetConfig.integration.test.ts [case29]`) exercises `divergent`, and no cell named it.
added here per `rule.require.experience-catalog-evolution`.

⚠️ **it is structural, never chosen.** the org is a property of the **parsed static config**, which
is loaded **per fill** — so there is no repo-wide read to hoist it to. that is the same asymmetry
the vision's awkward #6 names: `repo` is fixed once at factory time, the org is read on every load.

⇒ the drift is bounded, and the bound is what makes `divergent` a feature over a hazard:
`environment` is fixed per `genGetConfig` instance, so one process sees **one** choice and therefore
**one** org. two orgs never coexist in a run — they differ across deployments. ⇒ `divergent` is
therefore expressible, and it is what makes a test-org sandbox a shape an author can build.

### G. consumer schema declares `organization` — is the field the consumer's own? (2)

| value | the consumer's zod schema | outcome |
|---|---|---|
| `declared` | the schema holds `organization: z.string()` | ✅ the field **survives** into the parsed config |
| `undeclared` | the schema omits it | the field is **stripped** by the consumer's own zod parse — never consumed, never deleted by us |

🔴 **also caught downstream by r5** (`genGetConfig.integration.test.ts [case30]`). the catalog
modelled the org as a **derive input** alone (axis B) and never as a field the **consumer owns**.

⚠️ **the two roles are simultaneous, and that is the whole experience**: sdk-config READS
`organization` to derive a path, and the consumer's schema is *"the SOLE arbiter"* of what survives
the parse. a build that deletes the field before `safeParse` would keep every other test green and
break every consumer that reads its own org.

### H. repo slug shape — what the `repo` value looks like (3)

| value | shape | derived segments |
|---|---|---|
| `plain` | `svc-x` | **4** — `/{org}/svc-x/{choice}/{keyPath}` |
| `org-doctored` | `ahbode/svc-x` — the pre-behavior hack | **5** — `/ahbode/ahbode/svc-x/…`, the org lands twice |
| `scoped` | `@ehmpathy/svc-x` — a scoped package name | **5** — `/ehmpathy/@ehmpathy/svc-x/…`, the scope is its own segment |

🟡 **both five-segment values are ALTERPATHS, and each has a workable remedy**: drop the hack
(`org-doctored`), or pass `repo` explicitly (`scoped`). they are itemized here because the first
walk claimed *"the derive is uniformly four segments for every repo"*, and that claim does not hold
for either value.

⇒ **no de-duplication is attempted, on purpose.** sdk-config cannot tell an org-doctored `repo`
from a real one, so it does not try (`asSdkConfigPath.test.ts [case8]`/`[case9]` pin both).

## the product

`3 actors × 3 org-supply × 2 uri-form × 2 param-state × 2 tenancy × 2 org-agreement ×
2 schema-declares × 3 repo-shape` = **864 cells**.

🔴 **the three new axes multiply the space by 12 and add exactly FIVE distinct experiences**:
`F = divergent` (1) · `G = declared` and `G = undeclared` (2) · `H = org-doctored` and `H = scoped`
(2). ⚠️ **that ratio is the same one F11 measured, in the other direction** — there, one degree of
freedom charged 24 cells for one experience and was **cut**; here, three axes charge 792 cells for
five experiences and are **kept**, because each names a behavior a real test already exercises.

⇒ **the parts are not symmetric, and the asymmetry is the point.** F11 cut a freedom **nobody
asked for**; these three axes were discovered *downstream*, from tests that already passed. a cell
you can delete is a cost; a cell that holds a live behavior is a **debt the catalog owed**.

🔴 **it was 96, and F11 cut 24 of them.** one degree of freedom — the `org` argument — was a *value*
on axis B, so its removal did not subtract 1 experience. it removed **B's whole quarter**, paired
with every value of `A`, `C`, `D`, and `E`: `1 × 3 × 2 × 2 × 2 = 24`.

⇒ **that is the measurement `rule.forbid.combinatorial-explosion` names**
(`ehmpathy/rhachet-roles-ehmpathy#674`): a degree of freedom **multiplies** the experience space and
does not add to it. one optional key was 24 cells, and every one owed a verdict.

## orthogonality — and the seven inert regions the walk exposed

the axes are independently settable (every tuple is expressible), so the box is honest. but the
walk surfaced **seven** regions where a value makes another axis **inert** — the cell exists, the
experience does not vary — and **one** region that is impossible by nature. each is named here,
because each is an invariant:

1. **`C = explicit` makes B inert — across the VALID half.** an explicit path passes through
   untouched, so whichever org is declared, one identical experience results. ⇒ the invariant:
   **the org segment never mutates an explicit path** (wish acceptance #3). ⇒ the 2 cells at
   `config-field × explicit × D` are **2** distinct experiences — one per `D` value (present fills ·
   absent errors).

   🔴 **F8 narrowed this region.** it once covered all four B values, on the ground that an
   unread org cannot affect an untouched path. under a **required** field the org is read whether
   or not a derive needs it, so `absent × explicit` and `malformed × explicit` now **throw** —
   they moved out of this region and into region 3.

   🔴 **and F11 narrowed it again.** the valid half was `{config-field, override}`; it is
   `{config-field}` alone. ⚠️ **the region did not shrink in *experiences*, only in *cells*** — the
   two sources yielded one identical outcome, which is exactly why the override earned no experience
   of its own here. ⇒ **a degree of freedom that bought zero distinct experience and cost 24 cells
   to verdict.**
2. **`A = author` makes D inert.** at authoring time no one has touched the store, so
   `present`/`absent` cannot yet be felt. the author's experience is `B × C` only.
3. **`B ∈ {absent, malformed}` makes BOTH C and D inert.** the refusal precedes the derive *and*
   the store read, so all four `C × D` combos under either invalid value are one experience.
   ⇒ two invariants, one per value:
   - **an absent org is never defaulted away** — no two-segment fallback exists to reach (F8, `case=2`)
   - **a non-literal org is never spliced into a path, and never quietly dropped either** (`case=4`)

   🔴 **F8 widened this region**, from `malformed × bare` to the whole invalid half. that is the
   trade the verdict makes explicit: **a larger forbidden region, and a smaller live one.**
4. **`C = explicit` also makes E inert.** an explicit path is hand-written per repo, so two orgs
   never collide on it — the collision is a property of a *derived* path alone. E is live only in
   the `C = bare` half, and now only in its **valid** quarter.

5. **`B ∈ {absent, malformed}` makes F, G, and H ALL inert.** the refusal precedes the parse, the
   derive, and the store read alike — so no choice file's org, no consumer schema, and no repo slug
   shape can vary what the actor feels. ⇒ **the invalid half of B collapses the three new axes to
   one cell each**, which is why 792 added cells hold only 5 experiences.
6. **`C = explicit` makes H inert.** the repo slug is spliced by the **derive** alone
   (`asSdkConfigPath.ts:47`); an explicit path never reaches it. ⇒ the invariant: **a doctored or
   scoped repo slug cannot mutate an explicit path** — the same guarantee region 1 gives the org.
7. **`G` is inert across every other axis.** whether the consumer's schema declares `organization`
   changes **what survives the parse**, never what path is derived — sdk-config reads the field off
   the *raw* static config, before the consumer's zod parse runs. ⇒ the invariant: **the derive is
   unaffected by the consumer's schema, and the consumer's schema is unaffected by the derive.**
   two independent readers of one field.

and one region is **impossible by nature**:

8. **`A = oncall × D = present`** — a value that resolved throws no error, so there is no failure
   to read. no experience exists; none to demo.

## how the 864 are accounted

🔴 **the A–E core is accounted first (72), then multiplied by F × G × H (12).** the three late axes
are **orthogonal to the core and to each other**, and each is inert across most of it — so the
multiplication adds 5 experiences, never 792. the inert regions they introduce are named in the
list above (regions 5, 6, 7).

first by A–D (36), then each doubled by E:

every actor contributes the **same 12** `B × C × D` cells. the actors differ only in how many of
those 12 are *live*.

🔴 **two verdicts re-scored this table, and they moved different numbers.** F8 left the **cell
count** untouched and cut the **distinct experiences** — an absent org is still a shape an author
can express, and it now yields a refusal over a path. F11 cut the **cells themselves** — an
`override` is not a shape anyone can express, by any means.

| actor | cells | distinct experiences | the rest |
|---|---|---|---|
| `author` | 12 | **4** — 2 refusals + 2 valid (`cf × bare`, `cf × explicit`) | 8 covered by inertness: D at author time, plus C+D under the invalid half |
| `runtime` | 12 | **6** — 2 refusals (absent · malformed) + 4 valid (`cf × bare × 2 D`, plus `cf × explicit × 2 D` with B inert) | 6 covered by inertness |
| `oncall` | 12 | **4** — 2 refusals + 2 valid-at-`D=absent` | 2 by inertness · 6 **impossible** (a value that resolved raises no error) |

12 + 12 + 12 = **36** cells. × 2 tenancy = **72**. E varies the experience only in the `C = bare`
half **and only under a valid org** — an invalid org refuses before the derive, so two orgs cannot
meet there either.

× 2 org-agreement × 2 schema-declares × 3 repo-shape = **864**. every cell has a verdict in
`1.vision.experience.case=_.md`, and the three late axes are verdicted as **regions** there rather
than cell-by-cell — regions 5–7 above make all but 5 of their 792 cells inert, and a per-cell walk
of an inert region would record one verdict 792 times.

⇒ 🟡 **the honest read of F8, stated as a number: the live surface shrank and the forbidden one
grew.** that is the shape of a verdict that trades a demo for a guarantee — fewer experiences to
have, and one of them impossible to have by accident.

⇒ 🔴 **the honest read of F11 is a different number, and it is the sharper one: 96 → 72 cells, and
the distinct-experience count fell by exactly ONE per actor.** the override bought a single new
experience — *"a caller pins a different org"* — and charged 24 cells of verdict for it. ⇒ **that
ratio is the argument**: a degree of freedom is priced by the product it joins, never by the one
experience that motivated it.

## the latent axes the walk did NOT find — and the THREE it missed

we looked for a hidden dimension behind the `explicit` collapse and found none — `explicit` is
inert because the derive is genuinely skipped (`asSdkConfigPath.ts:35`), not because two axes
were fused. the collapse is a real invariant, not a modelling error.

🔴 **but three axes WERE latent, and the first walk missed all three.** F, G, and H were each
surfaced **downstream**, by the `r5` peer review of the verification stone, from tests that were
already green:

| axis | the test that exercised it | why the walk missed it |
|---|---|---|
| **F** org-agreement | `genGetConfig.integration.test.ts [case29]` | the walk modelled the org as **one value per repo**; it is one value per **parsed file**, and files are loaded per fill |
| **G** schema-declares | `genGetConfig.integration.test.ts [case30]` | the walk modelled the org as a **derive input** alone, and never as a field the **consumer owns** |
| **H** repo-shape | `asSdkConfigPath.test.ts [case8]`/`[case9]` | the walk asserted *"uniformly four segments for every repo"*, which is false for two slug shapes |

⚠️ **each was a real behavior with a real test, and no cell named it** — the exact drift
`rule.require.experience-catalog-evolution` forbids (*"a test exists that exercises a path the
catalog never named"*). ⇒ the contract is grown here rather than the tests bolted on outside it.

🟡 **the honest lesson, and it is about the METHOD**: all three latents shared one root — the walk
took `A` (actor) as the only axis about **who holds a value**, and never asked *"which artifact does
each value live in, and when is that artifact read?"* F lives in the **choice file** (per fill), G in
the **consumer's schema** (per parse), H in **package.json** (per factory). three artifacts, three
read moments, three axes — and the first walk collapsed all of them into the runtime actor.

one axis was **considered and rejected** as non-orthogonal: *scheme* (`aws::param` vs
`aws::secret`). the derive is scheme-agnostic today (`asSdkConfigPath.ts:47` never reads
`uri.scheme`), so scheme does not vary the experience — it only widens the blast radius of the
same experience. it is carried as a fulcrum (F3), not an axis.

## 🔴 and THREE more were missed — I, J, K, found at i003

the `r5` review of the verification stone found three further axes, each exercised by a green test
that no cell named. **all three were raised at i002 and left unfixed**, then re-raised at i003 —
which is the sharper half of what it caught.

| axis | the test that exercised it | why the walk missed it |
|---|---|---|
| **I** repo-resolution | `getOneRepo.integration.test.ts` — seven refusals | the walk modelled `repo` as a value the caller **has**; it is a value the factory **resolves**, from a file that may refuse |
| **J** org-normalization | `getOneOrg.test.ts [case4]`/`[case5]`/`[case6]` | axis B graded the org's **validity** and treated every valid literal as one value — so the trim and the ungated charset had no cell |
| **K** keyPath-validity | `asSdkConfigPath.test.ts [case3]` | the walk modelled the keyPath as an **input**; it is **assembled**, and the assembly can yield empty |

🔴 **the root they share is NOT the root F/G/H shared, and that is why the first fix did not catch
them.** F/G/H were about *which artifact holds a value*. I/J/K are about the step **after** the
read:

> the walk modelled every value as **read or absent** — a binary — and never as **read, then
> transformed**. `repo` is RESOLVED, `org` is NORMALIZED, `keyPath` is ASSEMBLED, and each
> transformation carries a failure surface the binary cannot express.

⇒ **two method lessons now, from two rounds**, and the second only became visible once the first
was fixed. each value on this map owes two questions, never one: *which artifact holds it, and when
is that read?* — and *what happens to it between the read and the splice?*

🟡 all three are **alterpaths**, so per `rule.require.experience-catalog-evolution` they are
itemized and owe no demo. the rows are in `1.vision.experience.case=_.md`.
