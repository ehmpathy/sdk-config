# case=7 — the adoption journey: one session, six boundaries, two orgs

> cells: the whole `C=bare` column walked end to end, plus the `E=shared` tenancy value
> feel = **happy** overall, with two sharp edges crossed en route · care = **critipath**
> **the densest experience in the catalog — centered per `define.experience._.metric=boundary-density`**

🔴 **F8 rewrote this case's spine.** it opened on a **collision felt directly** — two repos derive
one path, and the collision ends when one side adopts. under a required `organization`, neither
side can boot un-namespaced, so **the collision is unreachable rather than fixable**, and the
asymmetric-adoption story it centered on evaporates: nobody adopts on their own schedule, because
nobody boots without the field.

⇒ that is the honest cost of the verdict, and it is recorded rather than smoothed over: **a
stronger guarantee bought with a weaker demo.** F8 carries the trade.

## narrative — maya migrates one service, while priya's service watches

ahbode and a partner org both run a service named `svc-notifications`, in **one** aws account.
that is the whole reason this wish exists, and it is the boundary no single-step demo touches.

**maya starts.** she deletes the hand-authored path and writes the template's bare line. her
config has no `organization` yet — and her deploy **throws at boot**, before any aws call, with an
error that names the field and the shape it feeds.

⇒ **the collision she would have hit is the one she never reaches.** the un-namespaced path
`/svc-notifications/prep/database.password` — where the *partner org's* param sits — is not a
place her config can land, because her config cannot start there. the wish's central defect is
**barred by construction**, over caught after the fact.

**she declares the org.** one line: `"organization": "ahbode"`. the derive lands at
`/ahbode/svc-notifications/prep/database.password`.

**the partner is in the same position, and hits the same wall on their own upgrade.** they declare
`"organization": "partner"` and derive `/partner/svc-notifications/prep/database.password`. two
services, one account, one repo name, two paths — and neither had to coordinate with the other,
because the requirement, never a negotiation, is what separates them.

⚠️ **what the requirement takes away**: neither side can defer. the wish imagined a template that
ships the bare line to one repo at a time while the rest sit still; under F8 every consumer meets
the wall on its next upgrade. adoption is now **compelled and simultaneous**, over voluntary and
staggered.

**she fat-fingers it first.** her initial attempt is `"organization": "$.at(aws::param/ahbode/org)"`
— she thought the org itself could come from the store. it throws before any aws call, names the
value, and teaches the two fixes. she writes the literal instead.

**the param is not there yet.** the derived path is the *target* convention; her param still sits
at the old explicit location. the error names the derived path verbatim, so she moves the value
and re-deploys.

**her cicd passwords never moved.** those lines are still explicit, and they filled untouched
through every step above — she never had to think about them.

## `[tn]` sketch — one walk, six boundaries

```ts
given('[case7] two orgs run a repo named svc-notifications in one aws account', () => {
  // the precondition the collision needs, stated rather than assumed:
  // NEITHER config declares an organization at [t0]. each side adopts on its own
  // schedule below — maya at [t2], the partner at [t4].
  //
  // TWO factories over ONE param store — that shared store is what makes a
  // collision possible at all (both repos are named svc-notifications).
  // each factory gets its OWN recorder (`supplied` / `partnerSupplied`), which is
  // what makes the collision observable: the assertion is that two separate
  // recorders hold the SAME path string.
  const getMayaConfig    = genGetConfig({ ...base, statics: MAYA_STATICS_NO_ORG,    repo: 'svc-notifications' });
  const getPartnerConfig = genGetConfig({ ...base, statics: PARTNER_STATICS_NO_ORG, repo: 'svc-notifications' });

  when('[t0] maya writes the bare uri, and NEITHER config declares an organization', () => {
    // 🔴 INVERTED by F8. this step once asserted the collision itself — two
    // recorders holding one identical path string. under a required org
    // neither config boots, so the collision is asserted by its ABSENCE.
    then('BOTH refuse to boot — neither reaches the shared path', async () => {
      const mayaError = await getError(async () => getMayaConfig());        // boundary 1: barred
      const partnerError = await getError(async () => getPartnerConfig());
      expect(mayaError).toBeInstanceOf(BadRequestError);
      expect(partnerError).toBeInstanceOf(BadRequestError);
    });

    then('and the colliding path was never derived by either side', async () => {
      await getError(async () => getMayaConfig());
      await getError(async () => getPartnerConfig());
      // ⚠️ THE assertion this case exists for, and F8 turned it inside out.
      // it once read `toEqual([...one shared path...])` on both recorders —
      // the collision, observed. it now reads EMPTY on both: the un-namespaced
      // path is not a place either config can land.
      expect(supplied.paths).toEqual([]);
      expect(partnerSupplied.paths).toEqual([]);
    });
  });

  when('[t1] maya declares organization as a $.at() placeholder', () => {
    const getMayaConfigBadOrg = genGetConfig({ ...base, statics: MAYA_STATICS_ORG_PLACEHOLDER });

    then('it throws before any aws call, and teaches the fix', async () => {
      const error = await getError(async () => getMayaConfigBadOrg());     // boundary 2: refusal
      expect(error.message).toContain('organization must be a literal string');
      expect(supplied.paths).toEqual([]);
    });
  });

  when('[t2] she writes the literal "ahbode", param not yet moved', () => {
    const getMayaConfigWithOrg = genGetConfig({ ...base, statics: MAYA_STATICS_ORG_AHBODE });

    then('it throws, and names the ORG-SCOPED path it asked for', async () => {
      const error = await getError(async () => getMayaConfigWithOrg());    // boundary 3: absent
      expect(String(error)).toContain('/ahbode/svc-notifications/prep/database.password');
    });
  });

  when('[t3] she moves the param to the derived path', () => {
    const getMayaConfigWithOrg = genGetConfig({ ...base, statics: MAYA_STATICS_ORG_AHBODE });

    then('the value fills, with no further config edit', async () => {
      await store.set('/ahbode/svc-notifications/prep/database.password', PARAM_VALUE);
      const config = await getMayaConfigWithOrg();                         // boundary 4: happy
      expect(config.database.password).toEqual(PARAM_VALUE);
    });

    then('the partner STILL cannot boot — its config is unchanged', async () => {
      // 🔴 INVERTED by F8. this step once proved adoption was ASYMMETRIC: the
      // partner kept deriving the no-org path while maya moved off it. under a
      // required org the partner derives nothing at all — it refuses, exactly
      // as it did at [t0]. what the step now proves is narrower and still
      // real: maya's adoption is INDEPENDENT of the partner's.
      const error = await getError(async () => getPartnerConfig());
      expect(error).toBeInstanceOf(BadRequestError);
      expect(partnerSupplied.paths).toEqual([]);
      // and maya is unaffected by the partner's broken state
      expect(supplied.paths).toContain('/ahbode/svc-notifications/prep/database.password');
    });
  });

  when('[t4] the partner hits the same wall, and declares organization: "partner"', () => {
    const getPartnerConfigWithOrg = genGetConfig({ ...base, statics: PARTNER_STATICS_ORG });

    then('it derives its own org-scoped path — both are namespaced now', async () => {
      await getPartnerConfigWithOrg();                                     // boundary 5: tenancy
      expect(partnerSupplied.paths).toEqual([
        '/partner/svc-notifications/prep/database.password',
      ]);
    });
  });

  when('[t5] maya re-reads her cicd passwords, still written explicitly', () => {
    const getMayaConfigWithOrg = genGetConfig({ ...base, statics: MAYA_STATICS_ORG_AHBODE });

    then('they were untouched through the whole walk', async () => {
      await getMayaConfigWithOrg();                                        // boundary 6: passthrough
      expect(supplied.paths).toContain(
        '/ahbode/svc-notifications/database/role/cicd/for-plan/password',
      );
    });
  });
});
```

## what the `[tn]` tests that the narrative does not

per `define.experience` — the two forms earn their keep only where each catches what the other
misses, so the timeline is written to **test** the story, never to echo it:

| the `[tn]` adds | the logical hole it probes |
|---|---|
| `[t0]` asserts **both** recorders are empty | the narrative says "barred"; only a two-sided empty assertion proves the shared path was never reached. 🔴 inverted by F8 — it once asserted both held the *same* string |
| `[t1]` asserts `supplied.paths` is **empty** | the refusal must precede the aws call — the narrative cannot show a call that never happened |
| `[t3]` asserts the partner throws while maya fills | adoption is **independent**, though no longer staggered. a one-actor story cannot show that one repo's broken config does not disturb its neighbour |
| `[t4]` asserts the partner's path, in the same run as maya's | the tenancy seam is a relation between two configs, invisible in a one-actor story |
| `[t5]` re-asserts the explicit path **after** four state changes | the narrative claims "untouched"; only a late assertion proves no step disturbed it |

## why this is the densest walk

| boundary | crossed at |
|---|---|
| the multitenant collision — the wish's whole motive, **barred** over fixed | `[t0]` (neither boots) → `[t4]` (both namespaced) |
| the malformed-org refusal | `[t1]` |
| the absent-param miss, with the derived path named | `[t2]` |
| the happy fill after the move | `[t3]` |
| the tenancy seam — two configs, one account, distinct paths | `[t4]` |
| the explicit passthrough, held across every step | `[t5]` |

six boundaries in one realistic session, versus six sterile one-step demos. and the interaction
the sparse demos cannot show: **the shared path is asserted empty at `[t0]` and each org's own
path is asserted filled at `[t3]`/`[t4]` — the same recorders, before and after** — which is the
only honest proof that the org segment does the job the wish asked of it.

## 🔴 what F8 cost this case, stated rather than smoothed over

| the demo, before | after |
|---|---|
| the collision **observed** — two recorders, one identical string | the collision **barred** — two recorders, both empty |
| adoption is **asymmetric**: one side moves, the other sits still | adoption is **independent**: one side's broken config does not disturb its neighbour |
| the org segment **fixes** a live defect | the org requirement **prevents** the defect from existing |

⇒ the guarantee got stronger and the story got thinner. the wish's central claim — *"two orgs, one
account, one repo name"* — is still crossed here, and it is crossed as a **refusal** over a
demonstration. a reader who wants to see the collision itself now has to imagine it, because no
reachable state produces it.

🟡 **that is a real loss for the criteria stage.** the strongest proof that the org segment does
its job would be an assertion that two configs *once* collided and now do not; F8 makes the first
half unreachable, so `[t0]` proves a **negative** where it used to prove a positive. worth naming
because a negative assertion is the easier one to write wrong.

## the fail-safes stay legible

density is breadth, never a substitute for a spotlight. the two sharp edges crossed here each
keep their focused case: `case=4` (the refusal) and `case=5` (the absent param). this journey
shows they compose; those cases show they fail safe.
