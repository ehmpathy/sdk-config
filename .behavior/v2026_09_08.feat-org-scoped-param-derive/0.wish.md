## .what

`asSdkConfigPath` derives a bare `$.at(aws::param)` placeholder to
`/{repoName}/{choice}/{keyPath}` today. teach it ~~an **optional** org segment~~ **a required org
segment**, so it derives:

```
/{org}/{repoName}/{choice}/{keyPath}
```

~~when no org is available, today's two-segment derive holds, unchanged.~~
**when no org is available, `getConfig()` throws** — before any store read, with an error that
names both remedies.

🟡 the original wrote this segment `{orgName}`; the vision renamed it **`org`**, also by the
wisher's verdict (F4). the two words below are left as they were written.

## .why

one aws account can host two orgs' repos in one ssm parameter store. absent an org segment,
two orgs that each ship a repo named `svc-notifications` collide on
`/svc-notifications/{choice}/...`.

⚠️ **this is measured, never hypothetical.** the issue cites svc-notifications' HEAD
`config/prep.json`, whose cicd param paths already carry an `ahbode/` org prefix — and whose
config already carries a top-level `organization` field. those paths had to be hand-authored as
explicit strings **because** the bare derive drops the org and so points at a param that is not
there.

the downstream consequence is why it matters now: a bare placeholder that derives
`/svc-notifications/prep/...` while the param lives at `/ahbode/svc-notifications/prep/...`
raises a `SupplyError` and `getConfig()` throws. so until the derive reproduces the path folks
actually store at, no template can ship the bare form.

## .acceptance

1. with an org available, a bare `$.at(aws::param)` derives
   `/{orgName}/{repoName}/{choice}/{keyPath}`
2. 🔴 ~~with **no** org available, it derives `/{repoName}/{choice}/{keyPath}` — byte-identical to
   today. this is backcompat, and it is the half most likely to regress unnoticed~~

   **AMENDED 2026-09-08 → with no org available, `getConfig()` throws**, before any store read.

   🔴 ~~the error names the `organization` field and the `org` argument, in a form that tells the
   two apart, so a caller is never sent to edit a field they never wrote~~

   **SUPERSEDED 2026-09-13 by F11 → there is no `org` argument.** the key was cut, so there are no
   two sources to tell apart: the error names the `organization` field and **one** remedy. the
   caller is never sent to edit a field they never wrote because there is no other field to edit.
3. an **explicit** path still passes through untouched, exactly as it does today

   ⚠️ **narrowed by the amendment**: this holds under a **valid** org. an absent or malformed one
   throws before the path is reached, since the org is read whether or not a derive needs it
4. the org has a declared **source**, not an override argument alone — a caller who must pass
   the org by hand at every call site has not been unblocked. the issue names two candidates (a
   config field, a package.json field); which one, and whether a third is better, is yours

   ✅ **settled 2026-09-08: the static config's `organization` field.**
   🔴 ~~the override stays, as the escape hatch rather than the mechanism~~

   **SUPERSEDED 2026-09-13 by F11 → the override is CUT.** the config is the one source, and
   `genGetConfig` has no `org` key. ⇒ this goes **past** what the criterion asked: it demanded a
   declared source *beside* an override, and there is no override at all. the escape hatch is a
   config edit — `"organization": "_"` derives `/_/{repo}/{choice}/…`, its own namespace (F5).
5. every one of 1–4 is covered by a test that goes **red** before the change and green after
   (`rule.require.clamp-edge-cases`).

   🔴 ~~⚠️ the clamp must assert the **absent-org** case too — a test that only proves the new
   segment appears would stay green if the derive grew an org segment unconditionally, which is
   the one regression that would break every extant repo~~

   **AMENDED → the clamp is replaced, never dropped.** the amendment grows the segment
   unconditionally *on purpose*, so that regression no longer exists. the clamp now guards the
   failure the **requirement** introduces: a build that forgets the throw does not fall back to
   two segments — it splices a blank and derives `//svc-x/…` or `/undefined/svc-x/…`.

   ⇒ the test seeds a real value at the **old** two-segment path, then asserts the store was
   **never read**. that is the one assertion that goes red on a quiet fallback which happens to
   work, which is the failure that would reach production.

## .the boundary — what is NOT in scope

- **migrate no params.** this teaches the derive a shape; it moves not one value in ssm. a
  param move is its own change, with its own blast radius
- **do not rewrite svc-notifications' explicit paths.** they are the evidence, and they keep
  working through acceptance #3. their cleanup is downstream of this, never part of it
- **do not touch the `persist-with-rds` template or the declapract auto-migrate fixer.** the
  issue names both as what this unblocks; both live in another repo and are separate asks
  (`rule.always.scope-onetime-lessons-to-the-behavior`)
- 🔴 ~~**do not make the org segment mandatory.** every repo that derives a path today does so
  without one~~

  **REVERSED 2026-09-08 — the org segment IS mandatory.** the ground the bound stood on was that
  every repo derives without one today; the measurement says otherwise: **0 repos** in `ahbode/*`
  or `ehmpathy/*` use the bare form at all, so no extant derive is disturbed. and **6 of 6**
  ahbode sdk-config consumers already declare `organization`, so the requirement costs them not
  one edit.

  ⇒ what the reversal buys: the un-namespaced path two orgs could collide on is **unreachable**,
  over merely avoidable. the wish asked to end a collision; the amendment makes it impossible to
  start.

  ⚠️ what it costs: an all-explicit repo — which consumes no derive at all — is still held to the
  requirement. that is deliberate (a lazier read would leave the weak opt-in alive), and it is the
  one place the amendment charges a repo for a value it will never read.
