# case=2 — no `organization` declared, and the config refuses to boot

> cells: `r1` (runtime · absent · bare · either) · `a1` (author) · `o3` (oncall)
> feel = **sharp** · care = **critipath** — the upgrade experience for every consumer that lacks the field

🔴 **this case inverted on the wisher's F8 verdict** (*"if omitted, failfast"*). it opened as
*"no org declared → byte-identical to today"*, the wish's acceptance #2. that derive no longer
exists: **`organization` is required, and its absence is an error.** the case survives, and its
claim is now the opposite of the one it was written for.

⇒ the record of what that strikes, and what it costs, is fulcrum **F8**.

🔴 **and F11 narrowed the remedy to one.** the error once taught two fixes — the field, or a
`genGetConfig({ org })` argument. there is no such argument, so it teaches **one**: declare the
field. ⇒ the *"names both remedies"* claim below is struck where it appears.

## narrative — the author who never heard of this change

sam maintains a service that has used sdk-config since launch. his config has no `organization`
key. his params sit at `/svc-x/prep/database.password`, where the derive has always put them.

sam bumps sdk-config to pick up an unrelated fix. he reads no release note.

**his next deploy throws at boot**, before any aws call:

```
BadRequestError: config lacks a required `organization` field
  hint: every sdk-config consumer must declare a top-level `organization` — it
        becomes the first segment of every auto-derived path, so two orgs' repos
        of the same name cannot collide in one param store. add
        `"organization": "your-org"` to the config. to opt a repo out of a shared
        namespace, declare a placeholder such as `"organization": "_"` — there is
        no way to derive without one
```

sam adds one line, redeploys, and moves the param to the derived path. two steps, both named by
the error.

🔴 **one source, so one remedy** (F11). the hint sends sam to exactly one place, and there is no
second place it could have sent him — which is the whole ergonomic the single source buys: a
reader of the error never has to choose which fix is theirs.

## why the loud break is the point, not a defect

the wish feared the **silent** version of exactly this — an org segment that grows unconditionally
and re-points every path with no one the wiser:

> *"a test that only proves the new segment appears would stay green if the derive grew an org
> segment unconditionally, which is the one regression that would break every extant repo"*

⇒ that hazard is real, and the failfast is what answers it. sam cannot deploy into the broken
state, because he cannot boot into it. **a break he sees beats a break he does not**, and the
error names both remedies in the line that reports it.

✅ **and sam is hypothetical today.** 6 of 6 ahbode sdk-config consumers already declare the field,
and the wisher closed the external half — *"no one uses this repo yet"* (Q9) — so it ships as a
**minor**. the break is real and its population is empty.

⇒ 🟡 **that is what makes this case a demo rather than a migration plan.** it pins the contract for
the consumer who *will* exist, and pays nothing for it now.

## `[tn]` sketch

```ts
given('[case2] a config with NO organization key + a bare aws::param placeholder', () => {
  // config/prep.yml:  database: { password: '$.at(aws::param)' }   ← no organization key
  // the config is the ONLY source, so an absent key means NO source supplies one.
  const getConfigNoOrg = genGetConfig({ ...base, statics: STATICS_NO_ORG });

  when('[t0] getConfig() is called after the upgrade', () => {
    then('it throws a BadRequestError', async () => {
      const error = await getError(async () => getConfigNoOrg());
      expect(error).toBeInstanceOf(BadRequestError);
      expect(error.message).toContain('organization');
    });

    then('the error teaches the ONE remedy', async () => {
      const error = await getError(async () => getConfigNoOrg());
      expect(error.message).toContain('`organization`');
      // 🔴 the F11 clamp, and it asserts an ABSENCE: one source means one
      // remedy, so the hint must NOT offer a call-site lever that does not
      // exist. this goes red the moment an `org` argument is re-introduced
      // and the hint grows a second fix.
      expect(error.message).not.toContain('genGetConfig');
    });
  });

  when('[t1] the same config, and a value DOES sit at the two-segment path', () => {
    // the STORE changes, not the config — a real value waits where the OLD
    // derive would have landed, so a quiet fallback has a value to hand back.
    beforeAll(async () => {
      await store.set('/svc-x/prep/database.password', THE_OLD_VALUE);
    });

    then('it still throws — the two-segment derive is unreachable, not preferred', async () => {
      const error = await getError(async () => getConfigNoOrg());
      expect(error).toBeInstanceOf(BadRequestError);
    });

    then('and the store was never read at all', async () => {
      await getError(async () => getConfigNoOrg());
      expect(supplied.paths).toEqual([]);   // ← this is what makes [t1] ≠ [t0]
    });
  });

  when('[t2] a config that DOES declare organization, same upgrade', () => {
    const getConfigWithOrg = genGetConfig({ ...base, statics: STATICS_ORG_AHBODE });

    then('it boots, and every derived path carries FOUR segments', async () => {
      await store.set('/ahbode/svc-x/prep/database.password', PARAM_VALUE);
      await getConfigWithOrg();
      expect(supplied.paths).toEqual(['/ahbode/svc-x/prep/database.password']);
      expect(supplied.paths[0]!.split('/').filter(Boolean)).toHaveLength(4);
    });
  });
});
```

## 🔴 the clamp this case owes — and it is NOT the one the wish asked for

the wish's acceptance #5 demanded a clamp on the **absent-org derive**, to catch an org segment
grown unconditionally. F8 makes that segment unconditional **on purpose**, so that clamp has no
regression left to catch.

⇒ **a new one replaces it, and it guards the failure the requirement introduces**: a build that
forgets the throw does not fall back to a two-segment path — it splices a blank, and derives
`//svc-x/prep/…` or `/undefined/svc-x/prep/…`, which is an aws-invalid name at best and another
repo's namespace at worst.

| the clamp | goes red when |
|---|---|
| `[t0]` — absent org throws | the throw is dropped, whatever the derive then does |
| `[t1]` — `supplied.paths` is empty | the throw is dropped **and** a fallback quietly finds the old value — the silent-regression case, which is the one that reaches production |
| `[t2]` — a declared org yields exactly 4 segments | a blank org splices, or the segment count drifts |

**`[t1]` is the load-bearer.** it is the only step that fails on the specific defect a reviewer
would call harmless: a fallback that works. seed the store, and the fallback becomes visible.

## what this case pins

- absent org ⇒ **a throw**, before any store read (F8, ruled — this replaces wish acceptance #2)
- 🔴 the error names the **field**, and only the field (F11). one source, one remedy — and `[t0]`'s
  second `then` clamps that with a `not.toContain`, so the hint cannot grow a fix that does not exist
- a declared org ⇒ exactly four segments; no three-segment derive is left to reach
- ⚠️ **the two-segment template is deleted, never branched around.** `asSdkConfigPath` takes
  `org: OrgSlug`, so the absent case cannot be expressed at the seam that would splice it —
  `getOneOrg` refuses one level earlier (`rule.avoid.unnecessary-ifs`)
