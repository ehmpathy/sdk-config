# case=9 — `organization` is the CONSUMER's field, and it stays theirs

> 🔴 **added downstream, by the `r5` peer review of the verification stone.** the catalog modelled
> the org as a **derive input** alone (axis B: absent / config-field / malformed) and never as a
> field the **consumer owns** through the parse. a real test exercised it; no cell named it — the
> drift `rule.require.experience-catalog-evolution` calls a blocker.

> cells: `g1` (schema `declared`) · `g2` (schema `undeclared`) · exercised by
> `genGetConfig.integration.test.ts [case30]`
> feel = **happy** · care = **critipath** — *"the one behavior no other test in the repo could catch"*

## narrative — one field, two readers, neither aware of the other

the 6 ahbode sdk-config consumers wrote `organization` into their configs **years before** this
change, for their own schemas. F8 then made that same field a requirement of sdk-config.

⇒ so one key now has **two readers**, and they must not interfere:

| reader | reads from | when | what it does |
|---|---|---|---|
| sdk-config | the **raw** static config | before the parse | derives the first path segment |
| the consumer's zod schema | the same raw config | at `safeParse` | decides whether the field survives |

**neither knows about the other.** sdk-config reads the value and leaves it in place; the consumer's
schema is *"the SOLE arbiter"* of the parsed shape.

### what the consumer sees, both ways

```ts
// [t0] a consumer who declares it — svc-notifications, whose own code reads its org
const schema = z.object({ organization: z.string(), database: z.object({ /* … */ }) });
const config = await getConfig();
config.organization;   // 'test-org'  ← it survived. still theirs.
```

```ts
// [t1] a consumer who does not — a plain z.object strips unknown keys
const schema = z.object({ database: z.object({ /* … */ }) });
const config = await getConfig();
'organization' in config;   // false  ← stripped by THEIR schema, never by us
```

⚠️ **`[t1]` is where F8's cost is paid, and it is the reason the cost is zero.** F8 requires a key
the consumer may never have declared in their own schema. because a plain `z.object` strips unknown
keys, that requirement costs such a consumer **no schema edit at all** — the field enters the config
file and leaves at the parse, and their types are untouched.

### the hazard, and it will arrive dressed as a cleanup

*"we consume `organization` to derive the path, so we should strip it before `safeParse`."*

⇒ that reads as tidy, and it **breaks every consumer that reads its own org** — silently, since the
field simply stops existent in their parsed result.

🔴 **and every other test in this repo stays green while it does.** every other schema here OMITS
`organization`, and a plain `z.object` strips it anyway — so a build that deleted the field before
the parse produces **byte-identical** results in all 111 of them. `[t0]` is the only assertion in
the repo that goes red.

## `[tn]` sketch

```ts
given('[case9] the `organization` field belongs to the CONSUMER', () => {
  when('[t0] the consumer schema DECLARES it', () => {
    const schemaWithOrg = z.object({
      organization: z.string(),        // ← the consumer's own field
      database: z.object({ host: z.string(), port: z.number(), password: z.string() }),
      api: z.object({ key: z.string(), url: z.string() }),
    });

    const getConfig = genGetConfig({
      schema: schemaWithOrg,
      statics: `${TEST_CONFIG_DIR}/*.yml`,
      cache: createCache(),
      suppliers: [fakeParamSupplier, fakeSecretSupplier],
      environment: testEnv,
      repo: 'test-svc',
    });

    const result = useBeforeAll(async () => getConfig());

    then('the field survives into the parsed config', () => {
      expect(result.organization).toEqual('test-org');
    });
  });

  when('[t1] the consumer schema OMITS it', () => {
    // .note = the mirror clamp, and it guards the cost F8 imposes: we REQUIRE a
    //         key the consumer may never have declared. a plain `z.object`
    //         strips it, so the requirement costs them no schema edit.
    const getConfig = genGetConfig({
      schema: testSchema,
      statics: `${TEST_CONFIG_DIR}/*.yml`,
      cache: createCache(),
      suppliers: [fakeParamSupplier, fakeSecretSupplier],
      environment: testEnv,
      repo: 'test-svc',
    });

    const result = useBeforeAll(async () => getConfig());

    then('the config still parses, with the key stripped', () => {
      expect(result.database.host).toEqual('localhost');
      expect(result).not.toHaveProperty('organization');
    });
  });
});
```

## what this case pins

- **sdk-config READS `organization`; it does not own or consume it.** the value is taken off the raw
  config and **left in place** — whether it survives is the consumer's schema's call, and only theirs
- 🔴 **`[t0]` is the single assertion in the repo that catches a pre-parse strip.** every other
  schema here omits the field, so every other test is byte-identical under the defect. ⇒ **a
  critipath graded on COST, not on density**: one boundary, one axis, and a silent break of every
  consumer that reads its own org
- ⚠️ **`[t1]` proves F8's requirement is free for the consumer who never declared it.** the
  requirement lands on the **config file**, never on the **schema** — two different artifacts, and
  the test is what keeps them apart
- 🟡 **the two `when`s clamp opposite directions of one invariant**, and both are needed: `[t0]`
  catches a strip we would perform, `[t1]` catches a strip we would **prevent** (a build that forced
  the key through the parse would break the consumer who never asked for it)
- ⇒ **axis G is inert across every other axis** (`dimensions.md`, region 7): the consumer's schema
  changes what survives the parse, never what path is derived. two independent readers, one field,
  no interference — which is exactly the property these two tests assert
