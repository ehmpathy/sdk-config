## narrative — the repo whose params do not live under its own org

priya's repo sits in `ahbode`, and her params live under a platform org. she edits the one place
the org is declared:

```yaml
# config/prep.yml
organization: ehmpathy      # ← not the repo's own org. one line, one place.
database:
  password: $.at(aws::param)
```

the derive uses her value: `/ehmpathy/svc-platform-tools/prep/database.password`.

the same lever is the way out of every awkward cell: an org that must differ from the repo's own, or
a repo that wants no part of any declared org — the author writes whatever literal they want, and
`'_'` is the conventional stand-in for *"none of the declared ones"*.

⚠️ **there is no force-off.** the field cannot be omitted (F8) and cannot be `null` (F5). an author
who wants out of their org names a **different org**, never no org — so the derive is uniformly
four segments for every repo, and one that opts out lands in its own namespace rather than back in
the shared pool another org may hold.

the source, one line: **the config's `organization` field, or a throw.**

## `[tn]` sketch

```ts
given('[case6] a repo whose params do not live under its own org', () => {
  // TWO config dirs, never two arguments — the org is a property of the config
  // file, so the only way to vary it is to vary the file.
  const base = { schema, cache, suppliers, environment, repo: 'svc-platform-tools' };

  when(`[t0] the config declares organization: "ehmpathy"`, () => {
    // config: { "organization": "ehmpathy", "database": { "password": "$.at(aws::param)" } }
    const getConfigPinned = genGetConfig({ ...base, statics: DIR_ORG_EHMPATHY });

    then('the declared org is the one derived', async () => {
      await getConfigPinned();
      expect(supplied.paths).toEqual(['/ehmpathy/svc-platform-tools/prep/database.password']);
    });
  });

  when(`[t1] the config declares organization: "_" — the opt-out literal`, () => {
    // config: { "organization": "_", "database": { "password": "$.at(aws::param)" } }
    const getConfigOptedOut = genGetConfig({ ...base, statics: DIR_ORG_PLACEHOLDER });

    then('it lands in its OWN namespace, never back in the no-org pool', async () => {
      await getConfigOptedOut();
      expect(supplied.paths).toEqual(['/_/svc-platform-tools/prep/database.password']);
      // ⚠️ the assertion that carries F5: FOUR segments, not three. a repo that
      // opts out of its declared org does NOT fall back to the shared
      // /svc-platform-tools/... path, which is the one another org may hold.
      expect(supplied.paths[0]!.split('/').filter(Boolean)).toHaveLength(4);
    });
  });

  when('[t2] a caller tries to pass the org at the call site', () => {
    then('there is no such key', () => {
      // @ts-expect-error — there is no `org` key. the config declares it.
      genGetConfig({ ...base, statics: DIR_ORG_EHMPATHY, org: 'acme' });
    });
  });
});
```

## what this case pins

- the source is total and stated: **the config's `organization` field, or a throw**
- **a caller cannot force *no* org — only a *different* one.** the field takes a literal or the
  config does not boot (fulcrum **F5** + **F8**, ruled by the wisher). `'_'` is the conventional
  stand-in, and it derives a real fourth segment
- ⚠️ **`[t1]` is the assertion that carries F5, and it is a segment COUNT.** the opt-out yields
  `/_/svc-platform-tools/…` — **four** segments, not three. were the force-off restored, `[t1]`
  would derive the shared `/svc-platform-tools/…` path and the count assertion goes red. that is
  the whole difference between the two designs, made mechanical
- 🔴 **`[t2]` is the assertion that carries F11, and it clamps an ABSENCE.** a `@ts-expect-error`
  goes red the moment someone adds an `org` key back, which is the one break a runtime test cannot
  see. ⇒ **the space does not grow back quietly** (`rule.forbid.combinatorial-explosion`,
  `ehmpathy/rhachet-roles-ehmpathy#674`)
- ⚠️ **two config dirs, never two arguments.** the org is a property of the config file, so the only
  way to vary it is to vary the file — which is itself the demonstration that there is one source
