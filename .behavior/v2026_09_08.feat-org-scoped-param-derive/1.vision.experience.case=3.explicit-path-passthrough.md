# case=3 — an explicit path passes through untouched, whichever org is declared

> cells: `r7`, `r11` (runtime · **valid** org supply · explicit · present) · `a4` (author)
> feel = **happy** · care = **critipath** — it guards every live sdk-config consumer
> actor: **jordan**, a maintainer who upgrades and never learns this feature exists

🔴 **F8 narrowed this case's reach.** it once claimed passthrough *"org or no org"*, across all
four `B` values. under a **required** `organization` the two invalid values throw before any path
is reached, so the claim now holds across the **valid half only**.
⇒ `dimensions.md`, inert region 1, and its `absent`/`malformed` half now sits in region 3.

🔴 **and F11 collapsed the valid half to one source.** it read `config-field` *and* `override`;
there is no `org` argument, so `config-field` is the whole of it. the passthrough claim is
unchanged — what shrank is the set of ways an org can arrive to be inert against.

## narrative — jordan upgrades, and has no idea any of this happened

jordan maintains `svc-notifications` — the repo this wish cites. she is not part of the org-segment
work and has not read the issue. on a tuesday she bumps `sdk-config` to pick up an unrelated fix,
runs the suite, and deploys.

**nothing happens to her.** that is the whole experience, and it is the one this case exists to
protect.

what she never has to notice: every one of her `$.at(aws::param)` values is **explicit**,
hand-authored years ago precisely because the bare derive dropped the org —

```json
"password": "$.at(aws::param/ahbode/svc-notifications/database/role/cicd/for-plan/password)"
```

— and her config's first line reads `"organization": "ahbode"`.

so jordan sits on the exact cell where a careless change does the most damage: **an org is
available, and her paths are already written by hand.** had the org segment been spliced onto an
explicit path, her tuesday would have ended with `/ahbode/ahbode/svc-notifications/…`, a param that
belongs to no one, and a `getConfig()` that throws at boot — every secret at once, on an upgrade
she had no reason to scrutinize.

four peers would have had the same tuesday: svc-chat, svc-home-services, svc-jobs, svc-proknow each
write explicit param paths and each declare `organization`.

⇒ the guarantee jordan never sees: **an explicit path is the author's declared truth. the derive
never runs, so the org never touches it.** the org segment is inert here, by construction — and the
measure of this case's success is that no one ever has a story to tell about it.

## `[tn]` sketch

```ts
given('[case3] a config that declares organization + an EXPLICIT aws::param path', () => {
  // config/prep.json:
  //   { "organization": "ahbode",
  //     "database": { ... "password":
  //       "$.at(aws::param/ahbode/svc-notifications/database/role/cicd/for-plan/password)" } }

  when('[t0] getConfig() is called', () => {
    then('the supplier is asked for the explicit path verbatim', async () => {
      await getConfig();
      expect(supplied.paths).toEqual([
        '/ahbode/svc-notifications/database/role/cicd/for-plan/password',
      ]);
    });

    then('the org is NOT prepended a second time', async () => {
      expect(supplied.paths[0]).not.toContain('/ahbode/ahbode/');
    });
  });

  when('[t1] the same explicit path, from a config that declares a DIFFERENT org', () => {
    // 🔴 REWRITTEN by F8. this step once used a config with NO `organization`
    // key — which now throws, so it could no longer reach the assertion. the
    // inertness claim is the same and its witness changes: two DIFFERENT valid
    // orgs, one identical explicit path.
    const getPartnerOrgConfig = genGetConfig({ ...input, statics: STATICS_ORG_PARTNER });

    then('the path is identical — the org does not vary an explicit path', async () => {
      await getPartnerOrgConfig();
      expect(supplied.paths).toEqual([
        '/ahbode/svc-notifications/database/role/cicd/for-plan/password',
      ]);
      // ⚠️ the declared org is "partner" and the path still reads "/ahbode/…",
      // because that segment is jordan's own hand-written text, never a derive.
      expect(supplied.paths[0]).not.toContain('/partner/');
    });
  });

  when('[t2] the same explicit path, under the `_` opt-out org', () => {
    // 🔴 re-subjected on F11. it was `genGetConfig({ org: 'ehmpathy' })` — an
    // override — and there is no such argument. the third valid org value is
    // now the opt-out literal, declared in a third config dir.
    const getOptedOutConfig = genGetConfig({ ...input, statics: STATICS_ORG_PLACEHOLDER });

    then('still identical — no declared org reaches an explicit path', async () => {
      await getOptedOutConfig();
      expect(supplied.paths).toEqual([
        '/ahbode/svc-notifications/database/role/cicd/for-plan/password',
      ]);
      expect(supplied.paths[0]).not.toContain('/_/');
    });
  });
});
```

## what this case pins

- explicit ⇒ passthrough, unchanged (wish acceptance #3 — the one criterion F8 leaves intact)
- the `C=explicit` region is inert **across the valid org half** — `[t1]` and `[t2]` are the
  assertions that prove the inertness, over merely the passthrough. three different valid declared
  orgs yield one identical path
- ⚠️ **the inertness is now a two-value claim, never a four-value one.** an absent or malformed org
  refuses before the path is reached (`case=2`, `case=4` `[t2]`), so those cells left this region.
  a `[tn]` that asserted passthrough under an absent org would fail — which is why `[t1]` was
  rewritten rather than kept
- 🔴 **and the valid half is now one source, never two** (F11). `[t2]` once varied the *source* — a
  config field against an override — and varies the *value* instead. ⇒ the inertness claim is
  unchanged and the axis it is swept along is narrower, because the axis lost a value
