# c6 — the release waits for the commander's approval (sharp × criti)

## narrative

the commander wants no sdk-config release he has not read. the driver opens the pr and stops. ci runs; checks go green; the pr sits open. nothing ships: the release job runs only on a push to `main`, and nothing merges to `main` until the commander approves and a human enables the merge. the commander reads the pr body — the break, the 0.4.0 bump, the fulcrums — and approves. only then does `rhx git.release --apply` (gated by a human-held `git.commit.uses` quota) enable automerge.

the sharp edge: `main` has no branch protection (`gh api .../branches/main/protection` → 404). so the gate is conduct + quota, not github. the driver never runs `git.release --apply` and never merges before the approval; the route's verification stone ends at "pr open, checks green".

## fail-safe

- the release trigger is a push to `main` (`.github/workflows/release.yml`), and the driver never pushes to `main` (`git.commit.push` refuses main).
- automerge needs `git.release --apply`, which needs a human-granted quota.
- loud: the halt at the approval gate names the exact command the commander runs.

## timeline

```
given a pr open with checks green and no approval
when [t0] the driver reaches the end of its route
then the pr stays open
  and no release pr exists
when [t1] the commander approves and a human runs git.release --apply
then automerge lands the pr on main
  and the release job opens the 0.4.0 release pr
```
