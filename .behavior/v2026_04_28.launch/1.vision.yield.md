# vision: sdk-config

## the outcome world

### before

```ts
// manual cache wrap required
import ConfigCache from 'config-with-paramstore';
import { withSimpleCachingAsync } from 'with-simple-caching';

const configInstance = new ConfigCache();
const getConfig = withSimpleCachingAsync(
  async () => configInstance.get(stage),
  {
    cache: createCache({ ... }),
    serialize: { key: ({ forInput }) => [...].join('.') },
  },
);

// no type safety
const config = await getConfig();
config.databse.password; // typo not caught
```

### after

```ts
import { z } from 'zod';
import { environment } from 'sdk-environment';
import { genGetConfig, genSdkConfigSupplierAwsParameterStore } from 'sdk-config';

const schema = z.object({
  database: z.object({ host: z.string(), password: z.string() }),
});

export const getConfig = genGetConfig({
  schema,
  statics: 'config/*.{json5,yml}',
  cache: createCache({ expiration: { minutes: 5 } }),
  suppliers: [genSdkConfigSupplierAwsParameterStore()],
  environment,
});

const config = await getConfig();
config.databse.password; // typescript error!
```

### aha moment

when a developer:
1. writes `$.at(aws::param)` in yaml and it just works — no path construction
2. gets full intellisense on `config.database.password` from zod inference
3. deploys to prod and schema drift warns instead of crash at 3am

## user experience

### usecases

| who | goal | how |
|-----|------|-----|
| dev | access config in lambda | `await getConfig()` |
| dev | access static config sync | `getConfig.static()` |
| dev | validate config matches schema | zod schema + failfast in test/prep |
| ops | rotate secrets | update ssm, no code change |
| team | share cache across lambdas | swap in dynamodb cache |

### contract flow

1. define zod schema
2. create config/*.yml with `$.at()` placeholders
3. call `genGetConfig({ schema, statics, cache, suppliers, environment })`
4. use `getConfig()` anywhere

### timeline

- **t0**: install sdk-config, define schema
- **t1**: create config/test.yml, config/prep.yml, config/prod.yml
- **t2**: wire up getConfig in utils/config.ts
- **t3**: use everywhere via `await getConfig()`

## mental model

### how users describe it

> "it's like dotenv but for real secrets — you put `$.at(aws::param)` in your yaml and it fills in from parameter store"

### analogies

- **dotenv** but for aws secrets
- **terraform variables** but for runtime config
- **prisma schema** but for config shape

### terminology

| user says | we say |
|-----------|--------|
| "config file" | statics |
| "secret" | supplied value |
| "fill in the blanks" | `$.at()` resolution |
| "validate" | schema check |

## evaluation

### pros

- **type safety**: zod schema inference
- **pluggable cache**: any with-simple-cache backend
- **pluggable suppliers**: ssm, secrets manager, s3, more to come
- **env-aware validation**: failfast in test/prep, warn in prod/cloud
- **auto-resolution**: `$.at(aws::param)` derives path from repo + env + key

### cons

- **new syntax**: `$.at()` is unfamiliar
- **dependency on sdk-environment**: requires environment shape
- **async default**: getConfig() is async (but getConfig.static() is sync)

### pit of success

| edgecase | behavior |
|----------|----------|
| unknown `$.at()` uri | failfast — no supplier registered |
| schema drift in prod | warn only, no crash |
| absent env file | failfast — file not found |
| typo in config key | typescript error from zod inference |

## open questions & assumptions

### assumptions

- [x] users have sdk-environment wired up
- [x] users store secrets in aws ssm or secrets manager
- [x] users want yaml or json5 for config files
- [ ] `$.at()` syntax is intuitive enough

### questions

| question | status | answer |
|----------|--------|--------|
| should we support `.env` files as a supplier? | [answered] | no |
| should `getConfig.static()` also validate against schema? | [answered] | no — static() returns raw config with `$.at()` placeholders; validation would fail on placeholder strings |
| what's the fallback if ssm call fails? retry? cache stale? | [answered] | supplier retries internally, then failfast; no fallbacks, no stale cache |
| how does auto-resolution get repo name for ssm path? | [answered] | read from package.json name, overridable with explicit input to genGetConfig |
| should we support config inheritance? (base.yml + env-specific overrides) | [answered] | no — one file per environment |
| does prod/local and prod/cloud use same config file? | [answered] | yes — both have access='prod', same file; difference is validation strictness |

## what is awkward

1. **`$.at()` syntax** — unfamiliar, but concise; alternatives like `__PARAM__` or `${ssm:...}` feel worse
2. **environment as required input** — adds sdk-environment dependency, but ensures consistency
3. **async default** — most config access is async anyway in lambda; `getConfig.static()` covers sync case
4. **supplier generators** — `genSdkConfigSupplierAwsParameterStore()` is verbose, but explicit
