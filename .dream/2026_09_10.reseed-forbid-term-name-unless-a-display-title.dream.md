# 🌙 dream: forbid the term `name` unless its only purpose is a display title

**kind** reseed · **owner** `ehmpathy/rhachet-roles-ehmpathy` · **caught** 2026-09-10

## .the cue that fired

the wisher, mid-drive, immediately after F9 renamed `repoName` → `repo`:

> *"also, lets enqueue a dispatch into rhachet-roles-ehmpathy to forbid 'name' unless its
> literal only purpose is a display title, since its so commonly overloaded"*

⇒ the cue is F9 itself. `repoName` was **not** a display title — it held a slug that gets
spliced into an aws parameter path — and the suffix bought the reader no signal at all while it
broke the symmetry of the pair it belonged to (`org` + `repoName`).

## .the gap, precisely

`ehmpathy/role=mechanic` has a `lang.terms/` cluster with a live pattern of exactly this shape —
`rule.forbid.gerunds` names a **termsmell**, a word whose presence signals a defect beneath it:

> *"gerunds signal unclear domain: lazy placeholder"*

**`name` is the same kind of word and has no rule.** checkable evidence that it is overloaded,
all from this repo at the moment of the catch:

| the use | what it actually held | a truer word |
|---|---|---|
| `genGetConfig({ repoName })` | a path segment spliced into an ssm address | `repo` / `RepoSlug` |
| `getRepoName` | the op that reads that segment | `getOneRepo` |
| `package.json`'s `name` | the package identifier, third-party | — (not ours) |
| `withAssure(fn, { name: 'isUuid' })` | a diagnostic label for an error | ✅ display-adjacent, legitimate |

⇒ two of the four were a **slug** dressed as a `name`, and the rename of both is what F9 spent
its diff on.

🟡 **it also has a near-neighbour already in the cluster** — `rule.require.order.noun_adj` argues
for `[noun][adj]` so autocomplete groups by domain. `repoName` passes that rule (noun-first) and
is still the wrong word, so the prior rule does **not** already cover this.

## .the shape of the fix

a new brief at
`.agent/repo=ehmpathy/role=mechanic/briefs/practices/lang.terms/rule.forbid.term=name.md`,
shaped like its `lang.terms/` siblings (`rule.forbid.gerunds`, `rule.forbid.term=existing`):

- **.what** — `name` is forbidden unless the value's *only* purpose is a human-readable display title
- **.why** — a termsmell: `name` is the default word an author reaches for when they have not yet
  decided what the value IS. it survives review because it is never *wrong*, only never precise
- **.the test** — *"is this rendered to a human as a label, and never parsed, matched, keyed, or
  spliced?"* yes → `name` is legitimate · no → name the concept it actually is
- **.alternatives table** — `slug` (url/path-safe identifier) · `title` (display) · `label`
  (ui/diagnostic) · `key` (lookup) · `exid` (external id) · `handle` (@-style) · the domain noun
- **.exemptions** — a third-party contract you do not own (`package.json`'s `name`,
  an sdk response field); a `DomainEntity`'s genuine human-readable title
- **.enforcement** — `name` on a value that is parsed, matched, keyed, or spliced = **blocker** ·
  `name` where a domain noun exists = **nitpick**

⇒ the strongest single example to carry: **`repoName` → `repo`**, because the rename also fixed a
`rule.prefer.symmetric-term-pairs` violation the `name` suffix had created. one word, two rules
broken.

## .why it is not done in this round

**SAFE?** yes. **CLEAN?** 🔴 **no** — the fix lands in a different repo
(`ehmpathy/rhachet-roles-ehmpathy`), and this diff cannot reach it
(`rule.always.fix-forward-under-scouts-honor`: *"a fix that belongs to another repo → catch it as
a `reseed` dream"*).

## ⚠️ .caught, and NOT dispatched — one human command away

