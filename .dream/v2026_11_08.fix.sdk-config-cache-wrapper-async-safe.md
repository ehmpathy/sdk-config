# 🌙 dream: sdk-config caches its fill with an async-safe wrapper and a real key

kind: fix · owner: ehmpathy/sdk-config · caught 2026-11-08

## .the cue that fired
5.1 peer review (enroll-impl-arch-defects) on route `fix-release-on-decycled-cache`; reproduced by tsx probes on with-simple-cache 0.17.3 and 0.15.1.

## .the gap, precisely
`src/domain.operations/genGetConfig.ts:132` wraps the async fill with the sync `withSimpleCache`, which caches the promise:
- a rejected fill is cached and replayed until the entry expires (a transient supplier error sticks)
- an async cache's `get` returns a promise that reads as a hit → `getConfig()` resolves `undefined`, the fill never runs
- the wrapped fn takes no args → key is `JSON.stringify(undefined)`; two `genGetConfig`s on one shared cache collide

## .the shape of the fix
`withSimpleCacheAsync` + `cache: SimpleCache<unknown>` (sync or async); an explicit key from the declared org/repo/env config choice; tests: replay-free retry after a failed fill, async cache fill, two instances on one cache, concurrent cold calls. a 5.1 reviewer probe of 0.17.3 found `withSimpleCacheAsync` accepts sync caches, dedups in-flight, and stores no rejection — so the swap's only visible change is "no replay". the contract only widens. ⚠️ needs a wisher call: the F4 ruling named `SimpleCacheSync`.

## .why it is not done in this round
the director ruled the contract `SimpleCacheSync` (F4); the swap needs `SimpleCache<unknown>`. F7.
