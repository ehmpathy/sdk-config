the arrival is easy to miss because the dream reads as settled.

## 🔴 .the gap that is left, precisely

no mechanism stops the rename from drifting back. a future author who adds a supplier, renames a
scheme, or copies a stale snippet re-opens the identical defect, and the readme is not on any
test's path.

checkable: `asFilledConfig.ts:81-87` throws `BadRequestError('unknown scheme')` for any scheme with
no registered supplier. so a reader who copies a readme example verbatim gets a hard throw at
boot — **a broken paved path, which is worse than an absent doc.**

## .the shape of the fix

an acceptance-grade clamp that parses `readme.md` for `$.at(<scheme>...)` occurrences and asserts
each `<scheme>` equals the `.scheme` of a supplier the package exports.

- it reads a doc from a test, which is unusual here — so it wants a `.note` on why the doc is a
  contract surface (it is the wiring instructions a consumer copies)
- the exported factories are `genSdkConfigSupplierAwsParameterStore` and
  `genSdkConfigSupplierAwsSecretsManager` (`src/contract/sdk/index.ts`); each yields its `.scheme`
  with no aws call, so the clamp needs no credentials and could sit at unit grade instead

## .why it is not done in this round

SAFE — yes. CLEAN — **no.** items 1 and 2 were prose inside a diff that already opened the readme;
this is a new test file plus a doc-parse mechanism, and it clamps a surface this behavior never
touched (the s3 row, the supplier registry). that ripple is the CLEAN test failing, over a scope
excuse — the two docs edits rode along precisely because they did not have it.
