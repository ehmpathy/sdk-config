# 🌙 dream: a mechanic rule prescribes `useThen` / `useWhen`, which the pinned test-fns does not export

- **kind**: reseed — the rule lives in `rhachet-roles-ehmpathy`, not in this repo
- **owner**: unclaimed
- **caught**: 2026-09-10, mid `5.1.execution` of `v2026_09_08.feat-org-scoped-param-derive`

## .the cue that fired

self-review 7/8 (`role-standards-adherance`) flagged three adjacent `then` blocks in
`getOneOrg.test.ts` that each re-call one pure operation —
`rule.forbid.redundant-expensive-operations`. its remedy, stated in both that rule and
`rule.require.useThen-useWhen-for-shared-results`, is `useThen`.

i wrote the remedy exactly as the rule demos it. the suite would not even load:

```
TypeError: (0 , _testfns.useThen) is not a function
  at src/domain.operations/getOneOrg.test.ts:41:28
Tests: 0 passed, 0 failed
```

## .the gap, precisely

`node_modules/test-fns/dist/index.d.ts` at the pinned **1.7.2** — its whole public surface:

```ts
export { given, when, then } from './givenWhenThen';
export { genTestUuid } from './genTestUuid';
export { usePrep, useBeforeAll, useBeforeEach } from './usePrep';
export { getError } from 'helpful-errors';
```

⇒ **neither `useThen` nor `useWhen` exists.** the rule's every code block imports one:

```ts
import { given, then, useThen, when } from 'test-fns';   // ← no such export at 1.7.2
```

so the rule is unfollowable in any repo pinned here, and a mechanic who obeys it breaks
the suite at load — before a single assertion runs.

🟡 **the failure is worse than a normal one**, because it is a *suite-failed-to-run*: the
report reads `0 passed, 0 failed`, so a careless read of the summary sees no red tests.

## .the shape of the fix

one of two, and the choice is the reseeder's:

1. **bump the rule to the api that ships** — rewrite the demos on `useBeforeAll`, which
   1.7.2 does export, and keep `useThen` as a note about the newer line
2. **bump the pin** — confirm which test-fns minor first exports `useThen`/`useWhen`,
   then raise `test-fns` in the declapract template so the rule's demos compile

⚠️ either way the rule should **state the version it requires**. a rule that demos an api
with no version floor is a trap for every repo behind that floor, and the trap springs at
suite-load rather than at review.

🟡 `rule.forbid.redundant-expensive-operations` cites the same remedy and needs the same
edit — the two travel together.

## .why it is not done in this round

- **it fails CLEAN.** the rule text lives in `rhachet-roles-ehmpathy`, a separate repo. a
  local note here would drift from the source and help no other repo
- **the pin bump is not mine to take either.** `test-fns` is pinned by the declapract
  template, and a dependency raise carries its own blast radius
  (`rule.require.pinned-versions`)

## .what this round did instead

held the three `then` blocks as they were, with the reason written at the call site:
`getOneOrg` is a key read plus a trim, so it sits **outside** the cited rule's own scope
clause (*"operations >10ms or with cost"*), and the one remedy available at this pin —
a `useBeforeAll` hoist — would move a failure out of the assertion and into a hook shared
by all three, so one regression would report three times, at none of the lines that
describe it.

⇒ the sibling case that WAS fixed, for contrast: `asSdkConfigPath.test.ts` `[case6]`,
`[case7]`, `[case8]` shared their derive via a plain `const` at `when` scope. that works
because the operation returns rather than throws, so it needs no `useThen` at all.
