## .the cue that fired

a coverage review (`r8` of `5.1.execution`, `v2026_09_08.feat-org-scoped-param-derive`) walked
`practices/code.prod/evolvable.repo.structure/` and hit `rule.forbid.barrel-exports`:

> *"never do barrel exports … increase codepath variants, increase cyclical import chances, add
> zero value. **totally forbidden.** … no export forwarders."*

⇒ the cue was not the rule text. **the cue was that the defect had already happened, twenty
minutes earlier, and I had not connected it to a rule.**

## .the gap, precisely

there are two `index.ts` files, and `rule.forbid.index-ts` allows exactly two kinds:

| file | allowed by `forbid.index-ts`? | its importers |
|---|---|---|
| `src/index.ts` | ✅ **yes** — `package.json` `"main": "dist/index.js"` ⇒ it is the package entrypoint | `blackbox/sdk-config.acceptance.test.ts`, `blackbox/sdk-config.journey.acceptance.test.ts` |
| `src/contract/sdk/index.ts` | 🔴 **neither case** — not the entrypoint, not a dao | **only `src/index.ts`** + its colocated `index.acceptance.test.ts` |

so the public surface is declared **twice**:

```
blackbox/*.acceptance.test.ts   →  @src/index
src/index.ts                    →  ./contract/sdk     ← a HAND-MAINTAINED subset. the forwarder
src/contract/sdk/index.ts       →  ../../domain.*     ← the real barrel
```

### 🔴 the harm is measured, not forecast

`rule.forbid.barrel-exports` predicts *"increase codepath variants."* that is abstract. here is
the concrete instance, from the same review:

> **gap 12** — `OrgSlug` and `RepoSlug` were exported from `src/contract/sdk/index.ts` and **not**
> from `src/index.ts`. the two surfaces disagreed. a consumer could not import either type.
>
> ⛔ and **every gate stayed green**: 189 tests, `lint`, and every `src/` compile pass, because
> each in-repo file imports by relative path. only `blackbox/` reads `@src/index`, and only a
> clamp deliberately placed there caught it.

⇒ **the two-surface structure is what made a one-line omission invisible.** with one barrel the
omission cannot exist.

## .the shape of the fix

**take option B. it is the only one that removes the forwarder.**

| option | what it does | verdict |
|---|---|---|
| **A** — `export * from './contract/sdk'` | kills the hand-maintained list, so the disagreement is impossible | 🔴 **no.** it IS the barrel the rule bans, and it makes the public surface implicit |
| **B** — delete `src/contract/sdk/index.ts`, lift its content into `src/index.ts` | one `index.ts`, and it is the rule's allowed case 1 | ✅ **yes** |
| **C** — leave it, warn at the entrypoint | what this round did | a mitigation, never the fix |

option B, concretely:

1. move the 12 export lines of `src/contract/sdk/index.ts` into `src/index.ts`, verbatim,
   with their `.why` comments — the public surface must stay **byte-identical**
2. `rhx mvsafe` the colocated suite + its snapshot:
   - `src/contract/sdk/index.acceptance.test.ts` → `src/index.acceptance.test.ts`
   - `src/contract/sdk/__snapshots__/index.acceptance.test.ts.snap` → `src/__snapshots__/…`
3. its `from './index'` needs no edit — the relative path survives the move ✅
4. `rmsafe` `src/contract/sdk/index.ts`, and the now-empty `src/contract/sdk/`
5. ⚠️ **delete the `src/index.ts` warn added in this round** — it names a two-layer structure
   that will no longer exist, and a warn about a vanished hazard is worse than none

**the proof it is byte-identical**: `blackbox/*` imports 10 named exports from `@src/index`. if
`types` passes and both blackbox suites pass, the surface held. ⇒ the clamp already exists.

🟡 **the one real question B raises**: `contract/` is a declared bounded-context directory
(`rule.require.bounded-contexts`), and B empties it. either the sdk contract IS the package
entrypoint (⇒ B is right, and `contract/sdk/` was always a layer too many) or the directory earns
its place and `src/index.ts` should be a generated re-export rather than a hand-kept one. **B
takes the first read**, and that is the call a reviewer should push on.

## .why it is not done in this round

**SAFE?** ✅ yes — the surface can stay byte-identical, and `types` + `blackbox` prove it.

**CLEAN?** 🔴 **no.** it moves an acceptance suite and its snapshot, deletes a file inside a
declared bounded context, and restructures the public layout of a **published** package — all
inside a behavior about one path segment. that is the smuggled refactor the CLEAN question
refuses.

⇒ deferred, and the deferral is a **judgment about ripple cost**, so it owes a fulcrum beside
this dream: **F10**
