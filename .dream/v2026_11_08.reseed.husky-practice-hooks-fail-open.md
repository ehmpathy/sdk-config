# 🌙 dream: husky practice hooks fail open on a scanner error

kind: reseed · owner: ehmpathy/declapract-typescript-ehmpathy (practice `husky`) · caught 2026-11-08

## .the cue that fired
peer lanes on sdk-config route `fix-release-on-decycled-cache` (5.1 r006, r009, r004, r002, r007) graded the hooks the husky practice wrote into `.husky/`.

## .the gap, precisely
- `check.secrets.sh:48`, `check.timestamps.sh:67` — `line=$(… | grep -nIE … | head -n 1 | cut …)`: the pipeline status is `cut`'s, so grep exit 2 (bad regex, read fault) reads as "no match" and the commit passes. a secret scanner that fails open.
- `check.secrets.sh:48` — `grep -I` skips any blob grep classifies as binary; it is never scanned.
- `check.timestamps.lock.sh:44-45` — `git hash-object` failure yields '' and is reported as "hook changed" (ConstraintError, exit 2, remedy `declapract apply`) — a malfunction misread as a user act. the script omits `set -eu`.
- `check.secrets.sh:28`, `check.timestamps.sh:42` — the staged-file read aborts with a bare git error and a non-semantic exit.
- `check.timestamps.lock.sh:22-51` — `timestamps_lock_halt "$1" "$2"` positional at three call sites.
- no test or snapshot for any halt.

## .the shape of the fix
run each grep in its own `if` (or read `PIPESTATUS`): 0 → match, 1 → continue, ≥2 → `💥 MalfunctionError`, exit 1. scan with `-a`, not `-I`. guard `git hash-object` with the same `|| timestamps_lock_malfunction` the index read has; add `set -eu`. named args for the halt helper. acceptance tests in the practice that stage a fake secret / a raw clock / a bad regex and snap stderr + exit code.

## .why it is not done in this round
the files are practice-owned; `check.timestamps.lock.sh` forbids a hand edit. not CLEAN here.
