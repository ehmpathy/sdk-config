# 🌙 dream: every validation refusal in sdk-config is a `BadRequestError`, so `error.code.exit` cannot part a caller-fix from a server-fix

**kind** = repair · **owner** = `ehmpathy/sdk-config` · **caught** 2026-09-11

peer lane `r2 mech-failhides`, round 6 of `5.1.execution.from_vision`, graded a nitpick and named

> *"All of these new refusals are caller-fix conditions … yet there is no exit-code distinction

> this diff**."*

⇒ raised twice — `i003` and `i006` — by the same rubric, graded a nitpick both times, with the

## .the gap, precisely

`rule.require.exit-code-semantics` and `rule.require.failloud` grade an error by **class**:

| who fixes | class | exit |
|---|---|---|
| the caller | `ConstraintError` | **2** |
| the server | `MalfunctionError` | **1** |

so a CI job or a caller can branch on `error.code.exit` to decide *retry* against *repair the
input*.

**measured, 2026-09-11** — every refusal this repo raises is a `BadRequestError`:

```
src/domain.operations/getOneOrg.ts        absent org · malformed org · blank org
src/domain.operations/getOneRepo.ts       package.json absent/unreadable/unparseable/non-object
                                          · name wrong-kind · name absent · name empty
                                          · repo blank
src/domain.operations/asSdkConfigPath.ts  empty keyPath
src/domain.operations/genGetConfig.ts     validation failed · required values unread
src/domain.operations/asStaticConfig.ts   no config files · config file not found
```

⇒ **every one is caller-fix**, and not one is distinguishable at runtime from a server malfunction.

## .the shape of the fix

it is a **sweep**, and its cost is in the clamps, never the code:

1. map each validation refusal to `ConstraintError` (exit 2). the shapes stay identical —
   `ConstraintError` is a `HelpfulError` too, so `message` + metadata + `hint` survive verbatim
2. leave `MalfunctionError` for the genuine server-side cases. the supplier layer already raises
   one for a malformed ssm name, and that one is **correct** as it stands
3. 🔴 **every error snapshot in the repo changes** — the class name leads the message
   (`"BadRequestError: package.json not found"` → `"ConstraintError: …"`). measured: 5 suites hold
   error snapshots
4. **the public surface changes.** a consumer that catches `BadRequestError` by class no longer
   catches it. ⇒ it is a **semver major**, or it ships inside the same *"no external consumer
   yet"* window Q9 named — and that window closes the moment one adopts
5. re-snap, then dogfood one case per class to prove `error.code.exit` reads 2

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`):

- **SAFE?** ✅ the shapes are preserved; `ConstraintError` carries the same context
- **CLEAN?** 🔴 **no.** it touches **every** error site in the package, re-snaps 5 suites, and
  changes a **published** class contract — inside a behavior whose subject is one path segment

⇒ SAFE ✅ / CLEAN 🔴 is the row that reads *"defer, and raise a fulcrum."* and the peer that raised
it agrees in its own words: *"not a spot-fix in this diff."*

⚠️ **and a PARTIAL sweep is strictly worse than none** — half the refusals at exit 2 and half at
the generic default means a caller can trust neither, which is the state a `code.exit` check
exists to escape. that is what makes the fix atomic, and therefore its own change.
