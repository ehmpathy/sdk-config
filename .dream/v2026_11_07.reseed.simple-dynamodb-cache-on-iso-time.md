# 🌙 dream: @ehmpathy/simple-dynamodb-cache released on iso-time

kind: reseed · owner: ehmpathy/simple-dynamodb-cache · caught 2026-11-07

## .the cue that fired
sdk-config moved its cache contract to with-simple-cache 0.17.3 (iso-time). its readme example for the dynamodb cache stopped to fit.

## .the gap, precisely
`@ehmpathy/simple-dynamodb-cache@1.0.8` (latest): `dist/cache.d.ts:1,3,25` imports `UniDuration` from `@ehmpathy/uni-time` and `SimpleAsyncCache` from with-simple-cache (uni-time line). the iso-time contract hands `set` an `IsoDuration` that may be words; `UniDuration` cannot hold it.

## .the shape of the fix
bump with-simple-cache to 0.17.x; swap `@ehmpathy/uni-time` → `iso-time`; type `expiration?: IsoDuration | null`; `SimpleAsyncCache` → `SimpleCacheAsync`. ⚠️ today 1.0.8 already slips past sdk-config's tsc (its `SimpleAsyncCache` import no longer resolves → `any`) and fails silent at runtime. an iso-time release keeps that silent-accept hazard: sdk-config's `get: unknown` absorbs a promise. so sdk-config needs async-cache support (`.dream/v2026_11_08.fix.sdk-config-cache-wrapper-async-safe.md`) before the dynamodb example can return to its readme.
