# 🌙 dream: `radio.uses get` reports `global: not blocked` while the global blocker IS set

**kind** `reseed` — the defect lives in `bhuild/role=dispatcher`, not in this repo
**owner** whoever holds `rhachet-roles-bhuild`
**caught** 2026-09-18

## .the cue that fired

i needed to dispatch a fix upstream. i checked permission first, read `not blocked`, composed a
long issue body, and the push was then refused for the exact reason the check had cleared me on.

## .the gap, precisely

the two surfaces disagree, and both were run within one minute of each other:

```
$ rhx radio.uses get
   ├─ local: unset
   ├─ org:
   │  └─ ehmpathy: allowed
   │  └─ ahbode: allowed
   └─ global: not blocked          ⬅ says CLEAR

$ rhx radio.uses get --global
   └─ global: blocked              ⬅ says BLOCKED

$ ... | rhx radio.task.push --via gh.issues --into ehmpathy/...
✋ BadRequestError: radio.task.push blocked: global blocked
```

⇒ the **specific** read and the **enforcement** agree with each other. the **summary** read is the
one that lies, and the summary is what a caller checks first.

## 🔴 .the second observation, and it narrows the suspect list to one

the blocker was lifted the next day (2026-09-19) and both surfaces were re-read:

| | 2026-09-18 (blocked) | 2026-09-19 (clear) |
|---|---|---|
| `radio.uses get` → global row | `not blocked` | `not blocked` |
| `radio.uses get --global` | **`blocked`** | `not blocked` |
| enforcement | refused | ✅ created issue `#612` |

⇒ **the summary printed the identical string in both states.** so its global row does not merely
drift from the truth — on this evidence it never varied at all, which makes it a constant rather
than a stale read.

⚠️ **n=2, so this is a strong hint and not a proof** — two samples cannot rule out a read that
happens to be wrong in one direction. the check is one line: set the global blocker, run the
summary, and see whether the row ever prints `blocked`.

## 🔴 .why this is worse than a wrong label

`global` is documented as the **highest-precedence** lever: *"global blocked = always blocked"*. so
its row is the one a caller reads to decide whether any dispatch is possible at all.

- a caller who reads `not blocked` proceeds, composes the whole payload, and is refused at the end
- the cost lands **after** the expensive step, never before it
- and the refusal reads as a contradiction of a check the same tool just passed them, so the
  natural next move is to doubt the enforcement rather than the report

⇒ `rule.forbid.obfuscation`'s shape exactly: every individual surface is checkable, and the one a
caller actually reads gives them the wrong action.

## .the shape of the fix

the summary path almost certainly reads a different location, or a different default, than
`radio.uses.global.sh get` does. likely suspects, in order:

1. the summary composes its own read rather than a call into the global handler ⇒ **make the
   summary call the same operation the specific read calls**, so one fact has one source
2. or the summary defaults an absent value to `not blocked` while the global handler defaults it to
   `blocked` (the documented safe default is *"unset = blocked"*)

the files: `.agent/repo=bhuild/role=dispatcher/skills/radio.uses.sh` (the summary) and
`radio.uses.global.sh` (the specific), with `radio.uses.operations.sh` as the likely shared home.

⇒ a clamp is cheap and owed: set the global blocker, then assert **both** reads say `blocked`.
